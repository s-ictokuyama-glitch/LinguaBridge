# LinguaBridge

先生が話す日本語の授業音声を、同一LAN上の Windows 11 機でリアルタイムに音声認識・機械翻訳し、生徒が自分の端末（Chromebook / iPhone のブラウザ）で選択した言語の字幕として閲覧できるシステム。完全ローカル動作（APIキー不要・クラウド不要・GPU不要）。

- 全体計画: [plan.md](plan.md)
- 起動案内・QRの接続先: [Wi-Fi選択と復元の手順](docs/network-selection.md)
- PRD・実装スライス: [GitHub Issues](https://github.com/s-ictokuyama-glitch/LinguaBridge/issues)（PRD は #8）

## 現在の状態（イシュー #18 完了時点）

**ASR・翻訳とも実エンジンで動作する**: マイクの日本語発話が **ReazonSpeech K2 v2**
（既定・sherpa-onnx、`asr.engine: faster-whisper` で whisper small / kotoba へ切替可）で
文字起こしされ、**Hy-MT2-1.8B**（既定・GGUF/llama.cpp）または **NLLB-200 600M**
（CTranslate2、`mt.engine: nllb` で切替）で英語・中国語（簡体字）へ実翻訳されて
生徒カードに届く。実測遅延は発話終了→表示で中央値 0.65秒・最大 1.76秒
（開発機、docs/bench/2026-08-24-asr-gate.md）。

ASR の既定は判断ゲート②（#28）で確定した。ReazonSpeech は日本語 CER で
whisper small(9.62%) / kotoba(3.94%) を上回り（**2.09%**）、デコードは 10倍速い。
ただし**句読点を出力しない**（訳文には付くので生徒の字幕は影響を受けない）。

- 先生ページ（QR・参加コード表示、マイク→16kHz PCM16 のWS送信、開始/一時停止/終了、
  文字起こしライブ表示、**モニタリング**（2秒ごとの統計＝接続数・言語内訳・キュー深度・
  遅延中央値、マイク入力レベルメーター、30秒無音警告、キュー滞留の過負荷警告）、
  **記録トグル**（既定OFF・終了時にJSONL/言語別Markdownをローカル保存・生徒情報は含まない））
- サーバー（4桁コードの単一ルーム、**Silero VAD** 発話セグメンテーション（無音500ms確定・
  30s強制分割・プリロール240ms）、**幻覚フィルタ**（E-04: no_speech_prob /
  compression_ratio / avg_logprob / 既知フレーズ辞書）、起動時warmup、
  **アクティブ言語のみ翻訳・言語ごとに1回だけ翻訳**、言語別ブロードキャスト、
  再接続時の履歴差分再送＋**訳文が無い分のオンデマンド翻訳**、
  先生切断時の自動一時停止と再接続での自動再開、先生二重接続の後勝ち、
  参加コード総当たり対策（同一IP 5連続失敗で60秒拒否））
- 生徒ページ（コード入力→言語選択→字幕カード、言語の途中変更、原文併記トグル・
  文字サイズ3段階（再読み込み後も保持）・追従一時停止＋「最新へ」・UI多言語化
  （ja/en/zh）・遅延中タグ・状態バナー・**記録中インジケーター**、
  **指数バックオフの自動再接続**と切断バナー、seq順挿入・重複排除）

授業記録は先生ページのトグル（既定OFF）をONにした場合のみ、セッション終了時に
`sessions/<日時>/` へ `transcript.jsonl`（発話ごとの原文・全訳文・タイムスタンプ・計測値）と
言語別 Markdown（`transcript.ja.md` / `.en.md` / `.zh.md`）を書き出す。記録ON中は
先生・生徒双方の画面に「記録中」表示が出る。保存内容は先生の発話と訳文のみで、
生徒の個人情報・接続情報は含まない。クラウド送信は行わない。

実モデルが必要（下記「モデル取得」参照）。モデル・フィクスチャが無い環境では
該当する統合テストは自動スキップされる。

# 先生向け運用手順書

ITに詳しくなくても、**配布パッケージ（zip）を展開して `start.bat` をダブルクリックするだけ**で運用できます。
サーバーPCに Python などを入れる必要はありません。zip のダウンロードの後は、導入にも授業にも
インターネット接続は要りません（AI モデルは zip に入っています）。

## 導入（配布パッケージ・このPCで1回だけ）

1. **ダウンロード**: 担当者から案内されたクラウドの共有リンクから、
   `LinguaBridge-<日時>-<英数字>.zip`（約2.5GB）を1つだけダウンロードします。
2. **展開する前に「ブロックの解除」**: ダウンロードした zip を右クリック →「プロパティ」→「全般」タブの
   いちばん下の「セキュリティ」にある **「ブロックの解除」**（「許可する」と表示される場合もあります）に
   チェックを入れて「OK」。**必ず展開の前に**行ってください（展開した後では、中のファイルに印が残ります）。
3. **`C:\LinguaBridge\` に展開**: zip を右クリック →「すべて展開」→ 展開先に `C:\LinguaBridge` と入力して「展開」。
   `C:\LinguaBridge\start.bat` と `C:\LinguaBridge\app\` ができていれば完了です。
   - **ドキュメントやデスクトップには置かないでください。** 多くのPCでこれらは OneDrive と同期しており、
     モデルの読み込みが遅くなったり失敗したりします。OneDrive の中に置くと、起動時に黄色の注意が出ます
     （起動は続きますが、サーバーを止めてフォルダごと `C:\LinguaBridge\` へ移してください）。
4. **初回の起動**: `C:\LinguaBridge\start.bat` を**ダブルクリック**します。
   - 管理者の確認（UAC）「このアプリがデバイスに変更を加えることを許可しますか？」が1回出るので **「はい」**。
     これで Visual C++ ランタイムの導入・ファイアウォールの許可・AC 接続時のスリープの無効化・
     このPC用の証明書の作成がまとめて終わり、続けてサーバーが起動します（[毎授業の起動](#2回目以降の起動毎授業)と同じ画面）。
   - 次回からは管理者の確認は出ません。
   - 「いいえ」を押してしまった場合は、省いた項目とやり直し方が表示され、そのままサーバーは起動します。
     `start.bat` をもう一度実行し、今度は「はい」を押してください。
   - 初回に作られる `C:\LinguaBridge\data\` には、証明書・授業記録・現地で変えた設定が入ります。消さないでください。

> **SmartScreen の警告が出たとき**（手順2の「ブロックの解除」を忘れた場合）:
> 青い画面「Windows によって PC が保護されました」が出たら、**「詳細情報」→「実行」**を押します。
> 「ファイルを開く - セキュリティの警告」が出た場合は **「実行」**を押します。
> 最初の起動で `start.bat` が展開物に残った印を外すので、**2回目からは出なくなります**。

## 新しい版への更新

証明書・授業記録・現地で変えた設定は `data` に残るので、**`app` フォルダを差し替えるだけ**です。

1. サーバーのウィンドウを閉じて止めます。
2. 新しい zip をダウンロードし、**「ブロックの解除」をしてから**、別の場所（例: `C:\LinguaBridge-new\`）に展開します。
3. `C:\LinguaBridge\app` を削除し、展開した `C:\LinguaBridge-new\app` を `C:\LinguaBridge\` の中へ移します。
   **`C:\LinguaBridge\data` は消さずにそのまま**残します。
4. `start.bat` をダブルクリック。管理者の確認は出ず、前と同じ証明書で起動します
   （生徒端末での警告の承認をやり直す必要はありません）。

## 翻訳が遅いとき（NLLB への切替）

先生ページの遅延が大きい・「処理が追いついていません」が続くときは、同梱の軽い翻訳モデル
**NLLB** に切り替えられます。インターネット接続は要りません。

1. サーバーのウィンドウを閉じて止めます。
2. メモ帳で `C:\LinguaBridge\data\config.yaml` を開き（無ければ新しく作り）、次の **1行** を書いて保存します。
   新しく作るときは「ファイルの種類」を「すべてのファイル」にして、名前を `config.yaml` にします
   （`config.yaml.txt` にならないように）。

   ```yaml
   mt: { engine: nllb }
   ```

3. `start.bat` をダブルクリック。以後は NLLB で翻訳します。元に戻すときは、この行を消して起動し直します。

この設定は `data` にあるので、`app` を更新しても消えません。書き間違えると起動時にエラーが表示されて
サーバーが起動しないので、その場合は上の1行と見比べてください。

> **NLLB のライセンス（注意）**: NLLB-200 は **CC-BY-NC 4.0（非商用限定）** です。学校の授業での利用は
> 非商用の想定ですが、**商用の目的には使わないでください**。既定の Hy-MT2 は Apache-2.0 で制約はありません。

## 2回目以降の起動（毎授業）

1. `start.bat` を**ダブルクリック**
2. 黒いウィンドウに **参加コード**と**生徒用URL**が表示されます（授業中は閉じない）
3. モデルのロードが終わると、**先生ページが自動で開きます**
   - 自己署名証明書の警告が出たら、担当者の案内したIPを確認し、許可された環境で「詳細設定」から当該IPへ進む（再発行後にも警告が出る場合があります）。進めない場合は[証明書の復旧手順](docs/certificate-recovery.md)へ
   - マイクの許可を求められたら「許可」
4. 「開始」ボタンで配信開始。話すと生徒の端末に字幕が出ます

## 生徒の参加

- 先生ページに大きく表示される **QRコード**を読む、または **生徒用URL＋4桁コード**を入力
- 言語（英語／中国語簡体字）を選ぶと字幕が始まります
- 生徒ページは**警告なしのHTTP**で開けます（証明書の承認は不要）

## ネットワーク構成（2通り）

| 構成 | 使う場面 | 手順 |
|------|----------|------|
| **校内Wi-Fi直結**（主） | 校内Wi-Fiで端末同士が通信できる場合 | サーバーPCと生徒端末を同じWi-Fiに接続するだけ |
| **Windowsモバイルホットスポット**（副） | 校内WiFiが端末間通信を遮断（AP分離）する場合 | 下記 |

**ホットスポット構成の切替**:
1. Windows設定 →「ネットワークとインターネット」→「モバイル ホットスポット」をオン
2. サーバーPC自身がホットスポットの主なので、生徒端末をそのホットスポットに接続
3. `start.bat` を起動し直す（新しいIPでQRが再生成されます）

> ホットスポットは**同時接続8台**まで。10人学級では「2人で1台を見る」ペア閲覧や、
> 先生機自身は配信に使わない運用でスロットを節約してください。どうしても足りない場合は
> 安価なトラベルルーターの追加を学校に相談（無料要件の例外として要合意）。

## トラブルシューティング

接続の切り分けは、サーバーPCで起動ウィンドウを残し、別のターミナルから
`start.bat --diagnose` を実行してください。設定ポートを読み取り、OS設定を変えずに
接続先・待受・HTTP・TLS・ファイアウォールを確認します。
通常利用者は画面の「接続に困ったとき」、設定担当者は
[接続診断・復旧手順と記録欄](docs/connection-diagnostics.md)を参照してください。
この診断では既存の社内Wi-Fiでの直接接続を前提とし、変更対象をアプリとサーバーPCに限定します。

- **マイクが使えない/許可が出ない**: 先生ページはHTTPS（`https://…:8443/teacher`）で開いていますか。
  学校のChromebook等でHTTPS警告を承認できない場合は、サーバーPC上で
  `http://127.0.0.1:8000/teacher`（localhost）を開けばマイクが使えます。
- **生徒がつながらない**: 上の接続診断でサーバーPCと別端末の `/healthz` を比較してください。
  ping失敗やログ不在だけでAP分離とは断定せず、HTTP・TLS・ページ取得・WS参加を順に確認します。
- **起動時に「モデルが見つからない」等で止まる**: 配布パッケージのファイルが欠けているか壊れている
  可能性があります。zip を「ブロックの解除」をしてから展開し直し、[更新](#新しい版への更新)と同じ手順で
  `app` フォルダを差し替えてください（`data` はそのまま残します）。
- **「処理が追いついていません」の警告**: 早口・長文が続くと出ます。少しゆっくり、区切って話してください。
- **30秒無音の警告**: マイクがミュート/未接続の可能性。先生ページの入力レベルメーターを確認。
- **授業中にPCがスリープ**: 初回の管理者の確認で「はい」を押していれば、AC接続中は無効化されています。必ずAC電源に接続を。
- **翻訳が遅い**: [NLLB への切替](#翻訳が遅いときnllb-への切替)を参照。
- **翻訳ライセンス**: 既定の翻訳エンジン Hy-MT2 は Apache-2.0 で制約なし。`mt.engine: nllb` に切り替えた
  場合、NLLB-200 は **CC-BY-NC 4.0（非商用限定）** です。学校の授業利用は非商用の想定ですが、
  商用利用に転用しないでください。

# 開発者向け

## 開発セットアップ

```powershell
py -3.12 -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
```

## 開発機での起動（`start.bat`・開発モード）

開発機のリポジトリには同梱の Python（`app\python\python.exe`）が無いので、`start.bat` は `.venv` の開発モードで動く。

1. リポジトリの `start.bat` を**ダブルクリック**
2. 未セットアップと自動検出され、セットアップが始まる（数分〜数十分・要インターネット接続）:
   - Python仮想環境の作成と依存インストール
   - AI モデルのダウンロード（`%LOCALAPPDATA%\LinguaBridge\models` へ。約4GB）
   - 先生ページ用の自己署名HTTPS証明書の生成
3. セットアップ完了後、続けてサーバーが起動する

> ダウンロードが途中で止まっても、`start.bat` をもう一度実行すれば済んだ分はスキップして続きから再開する。
> 直らないときは `.venv` フォルダ内の `.setup-complete` を削除してから `start.bat` を実行すると、
> セットアップ（モデル再取得を含む）をやり直せる。

> **ファイアウォール許可とスリープ無効化まで自動化したい場合**は、初回だけ
> `start.bat` を右クリック →「管理者として実行」（省略しても起動はできるが、その場合はこの2つを手動設定する）。
> `setup.ps1` を単独で（右クリック→管理者として実行）先に済ませておいてもよい。

## 起動（手動）

```powershell
.venv\Scripts\python -m server.main                 # config.yaml を使用
.venv\Scripts\python -m server.main --open-browser  # 起動後に先生ページを開く（start.bat 相当）
.venv\Scripts\python -m server.main --config 別の設定.yaml
```

確定した公開IPに対して証明書（`certs/cert.pem`, `certs/key.pem`）のSAN・期限・鍵一致を確認できれば、HTTP(8000)とHTTPS(8443)を同時リッスンする。
不整合・未確認なら理由と再発行操作を表示し、HTTP単独で起動する（先生はサーバーPCの `http://127.0.0.1:8000/teacher` を使う）。
再発行・旧証明書と鍵の一組の復元・別端末の警告承認は[証明書の復旧手順](docs/certificate-recovery.md)を参照。
証明書は `python scripts\make_cert.py` で生成。死活確認は `/healthz`（常に200・liveness）と
`/ready`（モデルロード完了まで503・readiness）に分かれている。

## モデル取得とベンチ（イシュー #9）

```powershell
.venv\Scripts\pip install -r requirements-bench.txt      # 実エンジン系の依存
.venv\Scripts\python scripts\download_models.py          # 全モデルを1コマンドで取得
powershell -ExecutionPolicy Bypass -File scripts\make_fixture_audio.ps1  # ベンチ用日本語音声を合成
.venv\Scripts\python scripts\bench.py                    # 実機ベンチ → docs\bench\ に報告
```

モデルは OneDrive 同期を避けるため `%LOCALAPPDATA%\LinguaBridge\models` に置かれる
（`config.yaml` の `models.dir`）。判断ゲート①の結果と既定エンジンの根拠は
[docs/bench/2026-07-07-bench.md](docs/bench/2026-07-07-bench.md) を参照。
**学校の実機（i5）へ導入する前に同コマンドで再計測すること。**

## 配布パッケージのビルド（イシュー #46、ADR 0001）

開発環境の無いサーバーPC向けに、埋め込み版 Python 3.12・依存・コード・Web・配布用の既定の設定・
同梱モデル（reazonspeech-k2-v2 / hy-mt2 / NLLB）・`vc_redist.x64.exe`・版情報（`app\version.json`）を
まとめた zip を開発機で作る。同梱モデルは先に `download_models.py` で取得しておく（欠けていれば取得コマンドを示して止まる）。

```powershell
.venv\Scripts\pip install -r requirements-dev.txt   # DLL 依存の検査に pefile を使う
.venv\Scripts\python scripts\build_package.py       # → %LOCALAPPDATA%\LinguaBridge\dist\LinguaBridge-<日時>-<コミット>.zip
```

最後に自己検証（ネイティブDLLの依存先の検査・実エンジンの import・同梱の Python でのサーバー起動と `/ready` 200）を行い、
1つでも失敗したら zip を作らない。依存の版は開発機の `.venv` に揃える。
zip は `start.bat` と `app\` を含み、展開先（標準 `C:\LinguaBridge\`）で `start.bat` を実行すると、
`app\python\python.exe` があるため配布モード（`setup.ps1` を呼ばず、隣の `data\` をデータルート・
`data\config.yaml` を上書き設定にする）で起動する。同梱の Python が無いリポジトリでは従来どおり `.venv` の開発モード。

配布モードの初回（`data\.first-run-complete` が無いとき、イシュー #47）は、UAC の確認を1回出して
`scripts\first_run_admin.ps1` を昇格して実行する（VC++ ランタイムの無人インストール・HTTP/HTTPS ポートの受信許可・
AC 接続時のスリープ・休止の無効化。経過は `data\first-run.log`）。続けて昇格の外で同梱の Python から
`make_cert.py` を実行し、証明書を `data\certs\` に作る。昇格した処理が済んだらマーカーを書き、次回から UAC は出ない
（証明書が無いときは、UAC 無しで証明書だけを作り直す）。
「いいえ」を選んだ場合は省いた項目とやり直し方を表示してサーバーを起動し、次回また尋ねる。
ファイアウォールと電源の処理は `scripts\os_setup.ps1` にまとめ、`setup.ps1` も同じものを使う。

配布モードの起動時には、さらに次の2つを行う（イシュー #48）。どちらも起動は止めない。

- 配布パッケージのフォルダが OneDrive の配下（環境変数 `OneDrive` / `OneDriveConsumer` / `OneDriveCommercial`）
  にあれば、`C:\LinguaBridge\` へ移すよう警告する
- `app` 以下と `start.bat` に残った MOTW（`Zone.Identifier`）を `Unblock-File` で外す。1万ファイル超の走査に
  数秒かかるので、済んだら `app\.motw-cleared`（`version.json` の指紋入り）を書き、同じ版のあいだは走査しない
  （`app` を差し替えるか、上書きコピーで版情報が変わるとやり直す）

先生向けの導入・更新・NLLB への切替の手順は[先生向け運用手順書](#先生向け運用手順書)にある。

## 性能受け入れ試験（イシュー #17）

授業投入可否を機械判定する。45分の授業音声を実時間でリプレイ＋擬似生徒10接続で、
発話終了→表示の遅延分布・サーバー常駐メモリ・クラッシュ/切断復元失敗を計測し、
PRD の N-01（遅延 中央値≤5s/最大≤8s）・N-05（常駐≤5GB）・N-08（無停止・リークなし）に照らす。

```powershell
.venv\Scripts\python scripts\replay_client.py --audio 授業録音.wav   # 実録音で45分試験
.venv\Scripts\python scripts\replay_client.py --minutes 2            # 短縮スモーク（合成音源）
.venv\Scripts\python scripts\replay_client.py --minutes 2 --partial on   # partial字幕の A/B（#29）
.venv\Scripts\python scripts\replay_client.py --minutes 60 --corpus ja_ext  # 長時間連続動作試験（#32）
```

`--partial on|off` は partial字幕（先生のみ）の A/B 用。ドリフトを効果と読まないよう
**同じ時間帯に off → on を背中合わせで撮る**こと（#26 B-4 の教訓）。

`--corpus ja|ja_ext` はループ合成に使う音源。既定 `ja` は #17 以来の10文で、既存レポートとの
比較可能性を守るためのもの。`ja_ext` は #22 の拡張コーパス（35クリップ/200秒。話速×3・
文中の間・言い淀み・雑音SNR 20/10dB・無発話）で、**長時間試験はこちらで走らせる**。
`--langs en,zh` は生徒の言語配分。

45分以上の試験では、遅延ドリフト（5分窓ごとの中央値の推移）・スレッド/ハンドル/asyncioタスク・
ASR滞留とMTキューの増加傾向・破棄音声が判定に入る（#32）。「遅いか」ではなく
**「だんだん悪くなるか」**を見る指標なので、短いスモークでは窓が1つしか作れず判定されない。

`--mt-cache-size 0` は翻訳キャッシュを無効にして**MT負荷の上界**を測る。ループ合成の音源は
同じ原文が何周も来るためヒット率が実授業よりはるかに高くなり、既定のままでは Hy-MT2 が
ほとんど動かない状態を測ることになる（実測: 60分でヒット率 92.8%・MT 88回 → 無効で614回）。

`--disconnect-every-s 60` は**切断注入**（#35）。N秒ごとにランダムな生徒1名の接続を
close code 1001（going away＝端末スリープ相当）で切り、再接続の差分復元が効いているかを
**生徒ごとの seq 到達**で機械判定する。実授業で起きる Wi-Fi 瞬断を学校へ行く前に踏むためのもの。

```powershell
.venv\Scripts\python scripts\replay_client.py --minutes 45 --corpus ja_ext --disconnect-every-s 60
```

判定は「履歴上限（`history_resend`）の**内側**なのに最後まで届かなかった seq が 0 件」。
それより古い欠落は `joined.history_from` の契約どおりなので不合格にしない。注入した切断は
「想定外の切断」に数えない（数えると注入するほど不合格に近づく）。生徒の再接続バックオフは
1.0秒起点なので、注入間隔をそれより短くすると復元の失敗ではなく試験の設計ミスとして欠落が出る。

### スケーリングベンチ（`scripts\scale_bench.py`・#32）

生徒 1/10/20/40 × 対象言語 1/2/3/5 で推論回数を測り、**ASR回数が生徒人数で増えないこと**と
**翻訳回数が同一言語の人数で増えないこと**を数値で示す。

```powershell
.venv\Scripts\python scripts\scale_bench.py                  # 既定の行列（1点2分 × 16点）
.venv\Scripts\python scripts\scale_bench.py --students 1,10  # 軸を絞る
```

実エンジン（Hy-MT2 / NLLB）の対応言語は現在 `en` / `zh` の2つだけなので、**3言語・5言語の点は
MT を `fake` に落として回数だけを見る**（多言語対応は #5）。レポートは
`docs\bench\<日付>-scaling.md`。

既定エンジン（hy-mt2）が基準を満たさない場合は自動で NLLB を再測定し、合格した構成を
`config.yaml` の `mt.engine` 既定に反映する。レポートは `docs\accept\` に出力。
**授業投入前に学校の実機（i5）で実授業録音を `--audio` に与えて実行すること。**
合成音源（fixtureループ）は速度・安定性の確認用で、認識精度の確認は実地検証（#19）で行う。
