# 長い連続発話の検証範囲

先生が30秒を超えて話し続けても、分割した音声を順番に認識し、英語・中国語の字幕を更新し続けることを検査する。
実行手順と同期手順は [continuous-speechスキル](../../.agents/skills/continuous-speech/SKILL.md)、実行結果は [基準結果](continuous_speech_baseline.json) に置く。

## 既存検証との違い

[vad-segmentation](../../.agents/skills/vad-segmentation/SKILL.md) は8Hzの分割器単体を検査する。
既定Sileroで長い音声を入力する場合と、ASR以降は対象外である。
[silero-lesson](../../.agents/skills/silero-lesson/SKILL.md) は32ms処理からmorphの英中字幕までを検査するが、30秒以上の強制分割は対象外である。
[morph-lesson](../../.agents/skills/morph-lesson/SKILL.md) は短い断片の連結でTurn上限を通し、VADの30秒分割は通さない。

本検証は、音声の強制分割、持越し、認識断片の連結、翻訳配信を同じ入力でつなぐ。
途中字幕のASR競合も未検証の候補だが、途中字幕は既定で無効である。
今回は既定設定で起きる長い発話を優先した。

## 道具と期待値

Python 3.12.10で、固定した有限入力集合を実際の製品コードへ渡す。
asyncioとNumPyを含む実装の接続部分を調べるため、別言語の手書きモデルへ置き換えず、実コードに対する有界探索を使う。
SMTによる証明や任意の長さに対する証明ではない。

`SileroVAD`、`VoiceSegmenter`、`Pipeline`、`AsrBacklog`、`TurnAssembler`、`CaptionDelivery`、`Roster`、`ClientSender` は実装を実行する。
ONNX計算、音声認識、翻訳、通信相手は決定的な代役を使う。
音声分割とmorphは既定値を使い、MT待ち容量と復元抑制のしきい値は1件、監視の通知間隔は3,600秒に設定する。
操作後はイベントループを16回進めて、選んだ完了順序を実行する。
実装が出力したSegmentをそのまま正解にせず、元のPCMと事前に定めた分割位置から期待値を作る。
各ASR呼出しのPCMと期待区間を比較し、先生の確定文と英中字幕の内容・順序を照合する。

音声は16kHzのPCM16とし、512サンプルを1フレームとする。
全フレームを音声と判定させ、静かなフレームを周期的に配置する。
最静音位置の選び方によって持越しが大きい場合、小さい場合、持越しがない場合を通す。
受信チャンクは512サンプルと一致する場合と一致しない場合を含む。

## 有限入力集合

次の直積162ケースをすべて実行する。

| 軸 | 値 |
|---|---|
| 最静音フレームの周期 | 876、907、938フレーム |
| 受信チャンク | 511、512、1,600サンプル |
| 完了順序 | 逐次完了、ASRを保留して解放、MTを保留して解放 |
| 入力長 | 937、938、939、周期+937、周期+938、周期+939フレーム |

入力長は第1回と第2回の強制分割の直前・到達時・直後を表す。
ASR保留は次の分割前に解放し、ASR容量を超える負荷は与えない。
各ケースは残りをflushして排出する。そこまで成功したケースでは、さらに32フレームの音声を入力して英中字幕を比較する。
これは明記した3種類の完了順序の探索であり、全スケジューラ順序の全列挙ではない。

## 50分の仮想入力

無音を挟まない3,000秒のPCMを、1,600サンプルずつ30,000回入力する。
最静音フレームの周期は907フレームとし、ASRと各言語のMTは0.2仮想秒で完了する。
入力中はdrainを待たず、各Turnの強制分割が可能になった時刻の2仮想秒後から、最初の100ms刻みの観測時点までに英中字幕が増えることを確認する。
最後にflush、排出、次の短い入力への復帰を確認する。

ASRの保持秒数、翻訳待ち件数、分割前のPCM、Turnの保留断片、字幕履歴、翻訳キャッシュの最大値を記録する。
これは列挙した状態の保持量であり、プロセス全体のメモリー使用量の保証ではない。

## 時刻と字幕の確定

30秒は480,000サンプルで、512サンプルの整数倍ではない。
そのため分割上限に初めて達するのは938フレーム、30.016秒である。
分割器は直近2秒の63フレームから最も静かな位置を選び、後ろの音声を次のSegmentへ持ち越す。

一定振幅なら、最初の最小値にあたる876フレーム、28.032秒を認識へ渡す。
認識結果が継続語尾ならmorphはこの断片を保留する。
入力58.048秒で次の断片が確定すると、2断片の長さが56.064秒となり、Turnの30秒上限によって字幕が確定する。
このため、本検証は「30秒以内に字幕が届く」とは要求しない。

## 反例の読み方

`FAIL` の `trace` は入力条件と処理順序を表す。
`property` で違反した約束を確認し、`expected` と `actual` で最初の不一致を見る。
たとえば持越しを削除した場合、最初の強制分割後、次のASRへ渡るPCMが入力台帳の次の区間と一致しなくなる。
翻訳投入を削除した場合、先生へ確定文が届いても英中字幕が期待件数に達しない。

`--mutation-check` は `server/` の一時コピーに個別の破壊を入れる。
各破壊は正常版で成功する入力を使い、意図した性質の違反と終了コード1を要求する。
例外、終了不能、別の性質だけの失敗は検出成功に含めない。
通常版を再実行し、破壊前の結果との一致も確認する。

## 既知の反例

同期コミット `ea925f9ed3be791d96e24faa975a00ec4c81d99c` の製品コードで、持越しなしの強制分割後に短い音声が認識へ渡らない。[Issue #202](https://github.com/s-ictokuyama-glitch/LinguaBridge/issues/202) で追跡する。

1. 既定Sileroの全フレームを音声とし、938フレーム目が最も静かなPCMを入力する。
2. 938フレームで上限に達し、全量を強制分割する。持越しは空になる。
3. 続きの音声を1フレーム入力する。
4. 一時停止・終了と同じ `flush_audio` を呼び、drainする。
5. 合計480,768サンプルのうち、480,256サンプルだけが認識へ渡る。残り512サンプルはプリロールに残る。

`_maybe_force_close` が `_close(forced=True)` を呼ぶと発話開始状態に戻る。
続きの音声は開始条件の96msに達するまで `_pre_roll` に入り、`flush` は `_frames` が空なので何も返さない。
2フレームでも同じことが起き、3フレームまで続くと認識へ渡ることを分割器で別途確認した。
完全な512サンプル単位で起きるため、保証対象外の不完全フレームとは異なる。

検証器はこの反例を `pcm_partition` の失敗として残す。
残りの有限ケース、50分入力、正常な対照ケースを使う破壊検出も続け、復元後は同じ既知の失敗へ戻ったことを照合する。
製品コードはこの変更では修正しない。

## 破壊検出

| 破壊 | 検出する性質 |
|---|---|
| 持越しPCMを削除 | `pcm_partition` |
| 持越しPCMへ直前の1フレームを重複追加 | `segment_bound` |
| 強制分割の開始を倍の長さまで遅延 | `segment_bound` |
| morphの時間上限を無効化 | `turn_progress` |
| 翻訳ジョブ投入を削除 | `bilingual_delivery` |
| drainからMT排出待ちを削除 | `drain_completion` |
| 継続入力中の翻訳ジョブ投入を削除 | `sustained_progress` |
| 継続入力中のTurn保留を上限で確定しない | `retained_state_bound` |
| 長い音声をASR待ち行列で拒否 | `audio_admission` |

最初の6破壊は1,846フレーム、周期907、送信幅511、MT保留の固定入力を使う。
後ろの3破壊は64仮想秒の継続入力を使う。
保持量の検出器はTurn保留を増やす破壊で確認する。保持項目すべてを個別に破壊する検証ではない。
Silero入力とworker生存の確認は既存の検証器を再利用し、ここでは新しい独立性質として数えない。

## 基準結果

有限162ケースのうち144ケースが成功し、18ケースで上記の音声欠落を検出した。
失敗条件は周期938、入力長939または1,877フレームで、受信幅3種類と完了順序3種類のすべてに現れる。
JSONの `bounded.failures` に失敗した全入力条件を保存し、`violations` に性質ごとの最初の反例を保存する。
失敗件数だけで判断せず、条件と反例を照合する。

50分の仮想入力は成功した。ASRは105回で、末尾flushと次の短い入力を含めて英中それぞれ53字幕が届いた。
入力ループ中の保持ピークは、ASR音声29.024秒、MT待ち1件、分割前937フレーム、Turn保留1断片、字幕履歴50件、翻訳キャッシュ102件だった。
9種類の破壊はすべて想定した性質で失敗し、復元後は18ケースの失敗を含む通常版の結果と一致した。
このため全体の終了コードは1、`status` と `restored` は `FAIL`、`restored_matches` は `true` となる。

## 保証しないもの

入力集合の外にあるPCMや処理順序、実モデルの精度、実時間で50分間動かす性能は保証しない。
50分の入力は仮想時計で進め、推論時間と送信成功を前提にする。
マイク、LAN、WebSocketの実通信、生徒画面、先生交代、再接続、記録保存、モデルの永久停止は対象外である。
flush時に512サンプル未満の端数が残る場合も対象外とする。
これらは既存の各スキルと実際の授業環境で別に確認する。
