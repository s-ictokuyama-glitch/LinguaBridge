# 再接続字幕の有界検証

`caption_recovery.py` は復元対象の字幕について、配信完了か再接続の機会が残ることを実コードで確認する。
既存の [lesson-recording](../../.agents/skills/lesson-recording/SKILL.md) は翻訳と通信を対象外としている。
こちらは [caption-recovery](../../.agents/skills/caption-recovery/SKILL.md) で再実行する。

## 選定理由と道具

再接続復元が黙って失われると、生徒の字幕に穴が残る。
`web/student.js` の連続受信watermarkは欠落直前で止まるが、それ自体では再接続を起こさない。
`replay_history` は初回投入が混雑で拒否されたとき、1013切断して回収機会を作る。
投入済みのジョブは、言語が変わっても同じジョブ内で現在の言語へ配信する。
既存の `tests/unit/test_backpressure.py` は最初の復元投入拒否を調べるが、MT待ち中の言語変更と再投入拒否の組合せを調べていない。
同時controlは授業記録の検証と重なり、ASR順序はTurn構築の期待値も必要になるため、独立した字幕欠落を今回の対象に選んだ。

Python 3.12.10による有限操作列の全列挙を使う。
このPython asyncio実装のまま割込み順序を検証する道具は既存環境にないため、実コードに有限入力を生成する。
別のTLA+モデルは作らず、キュー・接続ID・言語変更・送信を実装どおり実行する。
これはSMTによる証明や無限状態の証明ではない。
依存は既存の `scripts/formal/requirements.txt` に固定している。

## 操作列と待機境界

最初に生徒なしでseq1を確定し、履歴へ保存する。記録はOFFとする。
復元要求を出さないen生徒とzh生徒を1人ずつ参加させる。
対象生徒をen、last_seq=0で参加させ、`Lesson.join` から実際の `replay_history` を通してseq1を投入する。
実際の `_mt_worker` を起動し、最初の `_process_mt_job` が `run_in_executor` で待つFutureを未完了に保つ。
この間に次の5操作を長さ0〜4の全列で与える。

| 操作 | 実行するコードと条件 |
|---|---|
| `set_en`、`set_zh` | 対象接続があれば `Lesson.set_lang` を実行する。除去済み接続には実装のcontains判定が働く |
| `live_turn` | 一意な原文を `CaptionDelivery.confirm` と `publish` に渡す。確定字幕の配信境界を入力にする |
| `disconnect` | 対象接続があれば `Roster.remove` で除去する |
| `rejoin` | 対象接続が名簿にない場合だけ、新しいsocketと接続IDでen、last_seq=0の `Lesson.join` を実行する |

対象生徒は最初の翻訳が止まっている間、字幕を受信しない。
そのため再参加のlast_seq=0はこの範囲の受信状態と一致する。
各参加時点の既存履歴を、その接続に対する復元対象として別途保持する。
操作の無効化・繰返しも列挙数に含める。異なる状態の個数ではない。

操作列の最後に最初のFutureを完了させ、その後の翻訳はフェイクエンジンで成功させる。
実際のMTワーカーと優先キューが全ジョブを排出するまで待ち、送信キューも排出してsocketが受信したJSONを読む。
`Roster` の送信先選択、`ClientSender` の送信タスク、`Lesson.join` の投入拒否時の切断を置き換えない。
実モデルのexecutorだけを制御可能なexecutorへ置き換える。
最初の翻訳待ち以外にも実際の接続除去に伴うawaitは動くが、人工的な割込みは追加しない。
`_enqueue_mt` の復元分岐や `set_lang` のように実際には制御を譲らない処理は途中で分割しない。

MTキュー容量は8、水位は1と2を別々に調べる。
最大4件の新着発話が2言語へ展開されても容量内に収まるため、この範囲では新着投入の容量待ちは生じない。
保持字幕は最大5件で、既定の履歴50件から失効しない。
全操作列は水位ごとに781列、計1,562列となる。
これに初回投入拒否2ケースと破壊用の正常な専用ケース4件を加える。

## 判定する保証

`replay_recoverable` は、最後に対象としている接続について、参加時の復元対象seqをすべて受信するか、1013切断することを要求する。
名簿から除去しただけでsocketを1013切断していない場合も、この保証を満たしたとは判定しない。
明示的な切断や再参加によって除去された古い接続の配信義務は破棄し、新しい接続の参加時点から計算する。
新着発話自体の完全配信は保証しない。新着はキュー混雑を発生させる入力として使う。

`replay_isolation` は、復元を要求していない2人にseq1が届かないことを要求する。
seq1は参加前の発話なので、ライブ配信の正当な受信と区別できる。
後続の全seqや全役割に対する誤配信の保証ではない。

`replay_language` は、対象接続が残る場合、受信字幕の言語が最初のMT完了前に確定した選択言語と一致することを要求する。
送信済み字幕の表示言語や、送信途中の言語変更は対象外とする。

`replay_duplicate` は、対象接続が同じseqを複数回受信しないことを要求する。

`screen_recovery` は、対象接続が受け取った `joined` と `caption` を、生徒ページと同じ `web/caption-recovery.js` に順番どおり渡す。Node.js で得たカードの順序、本文、`last_seq` を、送信内容から独立に計算した期待値と照合する。復元可能な字幕は画面モデルで連続確定することも確認する。

## #130 の検証結果

全1,568ケースで反例は0件だった。破壊6件をすべて検出した。
言語切替後の再翻訳は、すでに投入済みのジョブが引き受ける。水位で再投入を拒否されて字幕が欠ける経路がなくなった。
ライブ配信の宛先は発話確定時の接続IDなので、再参加で作られた新しい接続には `last_seq` に基づく復元が届く。

## 修正前の反例

同期コミット `f4f77289ca4a69b1c401cb39b4f93e5e70cb51a4` の [基準結果](caption_recovery_baseline.json) では、全1,568ケースのうち194ケースが `replay_recoverable` に違反する。
水位1と2で97ケースずつとなる。同じ原因の操作列を含む。
`violations` には保証と水位ごとの最短操作列を1件ずつ残し、件数を `occurrences` にまとめる。
`replay_isolation`、`replay_language`、初回投入拒否、正常な専用ケースには反例がない。

最短の反例は次の順序となる。

1. 生徒がenで再参加し、seq1の復元翻訳が待機する。
2. 同じ生徒の言語をzhに変更する。
3. seq2を確定し、enとzhのライブジョブを待機キューへ積む。
4. seq1のen翻訳が完了し、`_deliver_replay` がzhでの再翻訳を投入しようとする。
5. キューが水位以上なので `_enqueue_mt` がFalseを返すが、呼出側は戻り値を無視する。
6. 全ジョブを排出してもseq1は届かず、seq2だけが届く。対象接続は維持され、切断コードはない。

保存した反例の実行設定は水位1と2に限る。

## 破壊検出

`--mutation-check` は一時ディレクトリに `server/` をコピーし、各破壊に対応する正常な専用ケースが先にPASSすることを確認する。
その後、製品コードを一箇所だけ変更し、終了コード1と予想した保証違反の両方を要求する。

| 製品コードの破壊 | 正常ケース | 検出する違反 |
|---|---|---|
| 言語変更後の再翻訳分岐を無効化 | seq1のMT待ち中にzhへ変更し、新着字幕で履歴更新を打ち切る | seq1未受信、接続維持 |
| 対象接続への送信を言語全員への送信へ変更 | 言語変更なしでseq1を復元 | 要求していない生徒へのseq1誤送信 |
| 送信言語をジョブ開始時の言語に固定 | seq1のMT待ち中にzhへ変更 | zh選択中にen字幕を受信 |
| カード追加後の連続受信位置の更新を省く | 言語変更なしでseq1を復元 | `screen_recovery` がカードと `last_seq` の不一致を検出 |
| 字幕を二重に送信 | 言語変更なしでseq1を復元 | 同じ接続でseq1を二重に受信 |
| 初回投入拒否時のretryを削除 | 履歴2件、水位1で復元を要求し、その後排出 | seq1だけ受信し、seq2未受信のまま接続維持 |
| 初回投入拒否時のretryを単なる名簿除去へ変更 | 同上 | 未受信のまま1013切断も発生しない |

全7破壊を検出し、実行元の製品コードを変更せず、一時コピーを破棄する。
現在の製品コードでは正常ケースと全探索が通り、一時コピーで破壊した場合だけ想定した違反が出る。

## 範囲外

公平な排出と翻訳成功を仮定する。無限の言語変更や再接続は扱わない。
翻訳キャッシュを無効にし、既存の訳文を返す経路は偶発的に通る範囲に限る。
画面モデルには最後の接続のフレームと選択言語を渡す。接続をまたぐ状態、途中の言語切替、DOM 描画と履歴失効は Edge QA で確認する。
VAD、ASR、実翻訳モデル、翻訳失敗・制限時間超過、ネットワーク障害、送信キュー溢れ、授業終了、記録保存は保証しない。
実時間や全asyncioスケジュールの網羅も保証しない。
