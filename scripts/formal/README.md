# 授業記録の有界検証

字幕の再接続復元は別の [caption-recovery 検証](caption_recovery.md) と [スキル](../../.agents/skills/caption-recovery/SKILL.md) を使う。
ASR待ち行列の容量・順序・キャンセル後の排出は [asr-backlog 検証](asr_backlog.md) と [スキル](../../.agents/skills/asr-backlog/SKILL.md) を使う。
接続ごとの送信順序・障害時の1013切断・他接続への影響は [client-delivery 検証](client_delivery.md) と [スキル](../../.agents/skills/client-delivery/SKILL.md) を使う。
先生交代・切断・自動停止と再開は [teacher-lifecycle 検証](teacher_lifecycle.md) と [スキル](../../.agents/skills/teacher-lifecycle/SKILL.md) を使う。
認識断片の Turn 組立・確定条件・途中字幕の ID と版番号は [turn-assembly 検証](turn_assembly.md) と [スキル](../../.agents/skills/turn-assembly/SKILL.md) を使う。
音声の強制分割・受信チャンクの端数・flush をまたぐ PCM の保持は [vad-segmentation スキル](../../.agents/skills/vad-segmentation/SKILL.md) を使う。

`lesson_recording.py` は実際の `Lesson`、`Pipeline`、`SessionRecorder` に入力を与え、JSONL の発話を授業ごとに比較する。
Python の asyncio とファイル書込を含む実装への忠実さを優先し、別言語への手書きモデル化を避けた。
選んだ道具は Python による有限入力の全列挙であり、SMT による証明や無制限の形式証明ではない。
次回の変更では [lesson-recording スキル](../../.agents/skills/lesson-recording/SKILL.md) を使う。

## 調べる範囲

通常操作の探索では、初期の start と確定発話1件に続き、start、pause、end、確定発話、記録ON、記録OFFの全操作列を長さ4まで与える。
各列の最後に end を実行し、保存済みの発話集合を期待した授業別の集合と比較する。
1,555列を調べる。確定発話は最大5件、記録器の世代は最大3つとなる。
発話の入力境界は `_publish_turn` であり、ASR、文法判定、VAD の網羅を意味しない。
確定発話の操作は live のときにだけ発話を入力する。
最終保存されたファイルのバイト列が後の操作で変わらないことも確認する。
処理待ちの暫定保存は、同じ保存先へ遅着した発話・訳文を補うため更新される。

未完了 ASR の探索は、実際の `feed_audio` と `_asr_worker` を通す。
振幅1000の音声1件を、完了を手動制御できる executor で待機させる。
end より後に restart、その後に次授業の確定発話という順序を固定する。
ASR 完了をこの列の4箇所すべてに置き、restart が start と pause の場合を調べる。
pause で再開する場合は、その直後に start してから次の確定発話を入力する。
合計8順序となる。

30秒の待機自体は実行しない。
未完了の executor ジョブがあるとき、検証器が保存完了を待つ `wait_for` に `TimeoutError` を注入する。
呼出側の待機だけを中断し、バックグラウンドの ASR・MT 排出と最終保存は継続させる。
処理中の再開は ended のまま拒否されることを確認し、ASR 完了後に再試行する。
次授業の発話が再開拒否中に位置する順序では、再開成功後にその発話を入力する。
このシナリオでは ASR 上限を90秒に設定する。30秒の drain 超過を2回経ても ASR が未完了である順序を表す。
既定の ASR 上限60秒で、60秒以上経っても同じ ASR が完了待ちだという保証には使えない。
実際のタイマー、推論の性能、drain の実装の正しさは検証しない。

保存失敗は、再開2種類と障害2箇所の4ケースを実行する。
`SessionRecorder.write` の入口と、JSONL 保存後の最初の `_write_markdown` の入口で OSError を注入する。
失敗が続く間は ended と未保存の記録器を保持し、障害解除後に両授業の記録を保存できることを確認する。
JSONL の途中書込、後続の言語別 Markdown、プロセスクラッシュは調べない。

ファイルごとの発話をソートして比較するため、欠落、重複、授業間の混在を検出する。
ファイルの並び、発話順、seq、時刻、翻訳、Markdown の内容は保証しない。
生徒は接続しないため MT ジョブは発生しない。simple 戦略を使用する。
同時の control 呼出し、記録トグルと未完了 ASR の交錯、複数の未完了 ASR は対象外。

## 修正前の反例

同期コミット `30c3d455829c7ebb6615383c634d89fe41d87759` の製品コードでは、通常操作1,555列と保存失敗4ケースは成功する。
未完了 ASR の8順序では6順序で `recording_ownership` に違反する。
ASR が end より前に完了する2順序は成功する。
実行結果は [baseline.json](baseline.json) に記録している。

欠落は次の順序で起きる。

1. 授業Aで1件を確定し、次の音声を ASR 処理中にする。
2. end の drain が30秒でタイムアウトし、1件目だけを保存する。
3. ASR が完了し、2件目が保存済みの記録器へ追加される。
4. 再開時の保存は `_written` により何も書かず、記録器を交換する。
5. 2件目は JSONL に残らない。

混入は次の順序で起きる。

1. 授業Aの ASR を未完了のまま end し、drain をタイムアウトさせる。
2. start 時にも drain をタイムアウトさせ、授業Bの記録器へ交換する。
3. 授業Aの ASR が90秒の制限時間内に完了する。
4. `_publish_turn` が現在の記録器へ追加し、授業Bの JSONL に授業Aの文が残る。

タイムアウト時の部分保存自体は既存の仕様である。
この検証では、後から正常に確定した発話にも所属を保つことを要求する。
これらは [issue #115](https://github.com/s-ictokuyama-glitch/LinguaBridge/issues/115) の修正前の反例であり、baseline は比較用に保持する。

## タイムアウト後も元の授業へ保存する

保存待ちが30秒を超えた場合、現時点の内容を暫定保存し、先生に処理中であることを通知する。
待機のタイムアウトを理由に ASR や翻訳の結果を捨てない。
バックグラウンド処理が ASR、末尾の Turn、翻訳の順に排出し、追加操作がなくても同じフォルダへ最終保存する。
次授業への start と pause は、排出と最終保存が完了するまで拒否する。
最終保存に失敗した場合も、記録器と保存先を保持して再開を拒否し、次回の操作で保存を再試行する。
記録OFFで保存対象がないサーバー停止は排出待ちを省略するが、次授業への再開時は必ず排出する。

この方針では、同時に処理する授業を一つに保つことで遅着音声の所属を守る。
受理した発話の期待値は削らず、再開拒否時には期待モデルの授業世代も進めない。
記録 ON/OFF は既存の確定時判定を維持し、未完了 ASR と記録トグルの交錯は引き続き探索範囲外とする。
ASR 自身の制限時間超過、幻覚除外、過負荷による既存の破棄は、この保存待ちの方針とは別の規則である。

## 検出器を確認する

`--mutation-check` は `server/` の一時コピーに3つの破壊を別々に適用する。
授業を再開するときの記録器交換を削除すると、通常操作で所属の比較が失敗する。
再開前の保存待ちを削除すると、保存失敗中の再開拒否の確認が失敗する。
暫定保存を最終保存として封印すると、未完了 ASR の探索で所属の比較が失敗する。
それぞれ予想した診断と終了コード1を確認する。元の製品コードは変更しない。
baseline は修正前の2つの破壊検出を含む。
