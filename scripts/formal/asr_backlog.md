# ASR待ち行列の有界検証

授業記録の検証が前提としている ASR キュー排出と、再接続字幕の検証では扱わない音声の過負荷を対象にする。
音声の破棄は全生徒の字幕に影響し、完了通知の欠落は記録保存を止めるため、次の対象として選んだ。
先生の接続交代や送信障害も候補だが、今回は字幕と保存の共通の入口を優先した。

このリポジトリには Python の非同期実装を直接証明する検証器が導入されていない。
`AsrBacklog` の小さい状態空間を直接動かせるため、手書きの TLA+ モデルより低コストで実装とのずれを抑えられる有限入力の全列挙を使う。
これは SMT による証明や無限の入力に対する形式証明ではない。
実行と同期確認は [asr-backlog スキル](../../.agents/skills/asr-backlog/SKILL.md) に従う。

## 操作と原子性

容量1.5秒、16kHz、途中認識の下限1秒を固定する。

| 操作 | 実コードへの入力 |
|---|---|
| `seg1`, `seg2`, `seg4` | 0.5・1・2秒の異なる `Segment` を `offer` |
| `short`, `interim` | 0.5・1秒の `InterimSegment` を `offer` |
| `boundary`, `flush` | `TurnBoundary`、`FlushTurn` を `offer` |
| `take` | 単一タスクが `async with backlog.next()` に入り、内部で待機 |
| `finish`, `error`, `cancel` | 内部待機を正常解放、RuntimeError 注入、タスクキャンセル |
| `wait_cancel` | 空の `next()` を待機させてからタスクキャンセル |

12操作の長さ0〜4の全22,621列を列挙する。
`take` は待機イベントがあり、他の処理が進行中でない場合だけ許す。
`finish`・`error`・`cancel` は処理中だけ、`wait_cancel` は待機・処理中とも空の場合だけ許す。
不成立な列は除外する。正当な列では各操作後と末尾の正常排出後に性質を検査する。
各列で最大4イベントを投入し、末尾の排出は長さの上限に含めない。

`offer` は同期メソッドなので途中の割込みを作らない。
`next` はキュー取得から `yield` までと、`finally` の容量解放・`task_done` がそれぞれ制御を譲らない。
ワーカーの保持中にだけ他の `offer` を挟む。空の取得待ちのキャンセルも実タスクへ行う。
`join` は別タスクとして起動し、標準 asyncio イベントループの ready queue を1回進め、未完了イベントがあれば待機し、なければ完了することを検査する。
待機確認用の `join` タスクは都度キャンセルし、検証器が作ったタスクを残さない。
実時間経過や全イベントループのスケジュール順序は探索しない。

## 判定

期待値は受理したイベントの同一性と投入時のサンプル数のリストで管理し、製品のキュー内部や容量カウンターを読んで作らない。
確定音声は待機中と処理中の合計で容量判定する。ただし合計0なら2秒の音声も受理する。
途中認識は完全な空き状態かつ1秒以上の場合だけ受理する。境界・flush は容量に関係なく受理し、音声の容量には数えない。
取り出し順、深さ、待機・処理中・合計秒数、空き状態、破棄件数・秒数、途中認識省略件数を確認する。
正常終了・例外・キャンセルで同じ容量解放と完了通知を要求する。

`violations` は各性質で初めて見つかった反例を保持する。探索は短い列から進むため、列挙範囲内で操作数が最小となる。
`counts.legal` は検査を最後まで通過した正当な列の数で、失敗時の列数は `counts.violations` に分かれる。
不成立の列も、それまでの正当な接頭辞の検査は実行される。

## 破壊検出

一時ディレクトリに実際の `server/` と検証器をコピーし、各破壊を別々の Python プロセスで動かす。
元の作業ツリーの製品コードは変更しない。各専用列が元のコードで成功することを先に確認する。

| 破壊 | 専用列 | 必要な違反 |
|---|---|---|
| 容量判定から処理中音声を除く | `seg2,take,seg2` | `capacity` |
| FIFO を LIFO にする | `boundary,flush,take` | `fifo` |
| 処理中容量を解放しない | `seg1,take,cancel` | `accounting` |
| `task_done` を除く | `seg1,take,cancel` | `completion` |
| 混雑中の途中認識を許す | `boundary,interim` | `interim_admission` |

例えば、1秒の音声を処理中にさらに1秒を投入したとき、処理中を数えない破壊では容量1.5秒を超えて受理される。
キャンセル後の `task_done` を除く破壊では、音声がなくなっても `join` が完了しない。
終了コード1と指定した性質の違反の両方が必要で、例外や無関係の既存失敗は検出成功と数えない。

基準結果は [asr_backlog_baseline.json](asr_backlog_baseline.json) に置く。
同期コミットでは22,621列のうち正当な4,981列がすべて成功し、反例はなかった。実コードの破壊5件もすべて検出した。
推論の制限時間後に executor 内で動き続ける処理、可変 PCM の変更、ゼロ長音声、任意サイズ・任意容量、長期累積、複数コンシューマーは今回の範囲外である。
