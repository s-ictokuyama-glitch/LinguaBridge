# 既定morphの字幕継続

既存の `lesson-liveness`、`lesson-endurance`、`teacher-audio` はsimple戦略と文末で終わるASR代役を使う。`turn-assembly` は組立器へ認識断片と境界を直接与える。既定morphで、VADの境界がASR待ちとMTの背圧を越えて字幕まで届く部分が対象外だった。

この検証は、ASRが「温度が高いので」と返して保留された発話を扱う。長い無音、次の文末、一時停止で確定し、英中へ同じ順序で一度ずつ届けることを要求する。単体の状態機械を別言語へ写す代わりに、実PipelineへPCMを入力し、標準Futureの完了だけを制御する。実行手順と同期対象は [morph-lessonスキル](../../.agents/skills/morph-lesson/SKILL.md) にある。

第二候補は先生側WebSocketの送信滞留だった。`teacher.js` は `bufferedAmount` を確認せず送るが、許容する遅延や切断の規則には製品上の判断が要る。今回は既に存在するmorphの確定契約を先に検査した。送信滞留の不具合を確認したとは扱わない。

## 有限入力と期待値

8操作を長さ0〜4で全列挙する。4,681候補のうち1,548列が合法で、現行コードではすべて成功した。ASRまたはMTの完了対象がない列は非合法とする。各操作の後に16回のcallback処理を行う。列挙は短い順で、性質ごとに最初の違反を保持する。

| 操作 | 入力 |
|---|---|
| clause | 1秒の声と0.5秒の無音。認識結果はID付きの「温度が高いので」 |
| sentence | 同じ長さ。認識結果はID付きの「体積が増えます。」 |
| empty | 同じ長さ。認識結果は空文字 |
| boundary | さらに0.5秒の無音 |
| flush | 音声受理を停止、`flush_audio`、再受理 |
| asr | 現在のASR Futureを正常完了 |
| fail_asr | 現在のASR Futureを例外で完了 |
| mt | 現在のMT Futureを正常完了 |

期待値は入力時に作る `Fragment` と明示的なboundary/flushの台帳から計算する。製品の分類器・組立器や観測した字幕を期待値に使わない。空結果と注入したASR失敗を除き、継続断片を連結し、文末か境界で確定する。

各列の最後は、まずflushを呼ばずに受理済みASRとMTを完了させ、確定字幕を比較する。自然な境界の欠落を最後のflushで隠さない。その後、flushで残りを確定し、次の発話も翻訳できることを比較する。

音声は16kHz PCM16、100msごとに1,600サンプル。非ゼロ振幅が断片IDを表し、ASR代役が読み取る。energy VADと実プリロールを通し、ASRに複数IDが混在した場合も成功とは扱わない。翻訳代役は言語と日本語を返す。実推論モデルの品質や速度は測らない。

固定ケースは、長無音、flush、容量1のMT満杯、12断片上限、30秒上限の5つ。上限のケースはそれぞれ12個の1秒音声と、9個の3秒音声を0.5秒無音でつなぐ。各ASRを処理し、最後のflushなしに結合発話が届くことを要求する。長さ4の探索がこれらの上限を網羅したとは扱わない。

## 50分の入力計画

次の10秒を300回繰り返す。各断片に異なるIDを割り当て、翻訳キャッシュの同文ヒットだけで成功しないようにする。

| ブロック内の時刻 | 入力と期待する確定 |
|---|---|
| 0〜1.0秒 | 継続断片。次の0.5秒は無音 |
| 1.5〜2.5秒 | 文末断片。先行断片と結合し、3.0秒までの無音で確定 |
| 4.0〜5.0秒 | 継続断片。6.0秒までの無音で単独確定 |
| 6.0〜7.0秒 | 継続断片。7.5秒で一時停止・flush・再開して確定 |
| 7.5〜9.0秒 | 文末断片。9.5秒までの無音で確定 |

観測時刻は各100ms入力を渡したtickで記録するため、無音の確定時刻は上表より0.1秒早い。入力計画の4確定地点に8仮想秒の配信期限を設ける。末尾flushを追加せず、最後の10秒で処理が終わることも要求する。

ASR/言語ごとのMTの所要時間は0.1/0.2秒と0.8/0.8秒。発話ごとのdrainは行わず、毎100msに音声を入れ、完了時刻を迎えたFutureを解放する。これはこの所要時間を仮定した継続検査であり、開発機やサーバーPCの推論性能ではない。

各構成は30,000入力フレーム、1,500音声断片、1,200確定発話、英中各1,200字幕を要求する。字幕内容と順序は最後に全件比較し、途中は期限を確認する。音声破棄なしとワーカーの生存も検査する。

保持量の上限はASR音声30秒、ASR待機イベント8件、MT待機1件、保留断片12、履歴50、キャッシュ512、接続ごとの受信記録100、開始時タスク数+4。ASRイベント8件はこの入力計画の検査上限であり、任意の過負荷に対する製品の容量保証ではない。

MTの再送抑制閾値も1に設定する。統計配信間隔は3600秒へ延ばし、50分中の定期配信は発生させない。再接続復元と統計配信自体の検証は含まない。

## 故障注入と基準結果

基準結果は [morph_lesson_baseline.json](morph_lesson_baseline.json)。現行製品の反例は見つからなかった。元の製品コードは変更しない。

`--mutation-check` は一時コピーの製品コードを次の9通りに壊す。各破壊の前に正常対照を実行し、指定した性質と終了コード1を確認する。最後に元コードで全検証を再実行し、基準結果との一致を要求する。

| 破壊 | 検出する性質 |
|---|---|
| 長無音の境界を無視 | morph_turns |
| 境界を待機中ASRより先に処理 | morph_turns |
| FlushTurnを投入しない | morph_turns |
| 満杯のMT待ち行列への確定字幕投入を省略 | bilingual_delivery |
| MTの排出待ちを省略 | drain_completion |
| 境界処理時にASRワーカーを終了 | worker_liveness |
| 長無音による確定を100フレーム遅らせる | sustained_deadline |
| 字幕履歴の上限を削除 | retained_state_bound |
| 確定音声を受理せず破棄 | audio_admission |

代表的な反例は、継続断片を入力し、ASRの完了前に長無音の境界が届く順序である。境界を先に処理する破壊では、その時点の組立器が空なので境界が消費される。後から認識結果が保留され、字幕が0件のままになる。検証は最後のflushより前にこの欠落を検出する。

`Model the Domain` に従い、入力断片と確定地点を台帳にした。`Prove It Works` に従い、実コードの破壊と復元を実行した。製品の状態機械や設定は変更していない。
