# Turn 組立と途中字幕の有界検証

認識済みの断片を入力順に一度ずつ確定し、途中字幕を同じ発話 ID へ結び付ける。
違反すると、全生徒の字幕・翻訳・授業記録が欠落・重複するか、先生の途中字幕が別の発話へ混ざる。
既存の記録検証は simple 戦略だけを通し、ASR待ち検証は Turn 組立を除外しているため、この領域を選んだ。
次点は `VoiceSegmenter` の強制分割後の音声保持である。

## 実コードを実行する

`turn_assembly.py` は実際の `TurnAssembler` と `SurfaceBoundaryClassifier` を実行する。
別の台帳に入力した断片・発話 ID・版番号を記録し、公開メソッドの返す値と比較する。
台帳は製品の `_Pending`、分類結果、`_flush` を使わず、断片の末尾に期待する確定条件を入力表で指定する。
検証対象は同期メソッドなので、各呼出しを原子的な一操作として扱う。

Python 標準ライブラリーだけで実コードに全入力列を与えられるため、この方式を選んだ。
別言語の手書きモデル、SMT、無制限の形式証明は使わない。

```powershell
uv run --python 3.12.10 --no-project python -X utf8 -B scripts/formal/turn_assembly.py --mutation-check --json .audit/turn-assembly-result.json
```

Python 3.12.10 を使用する。追加依存はない。
このコマンドの基準結果は [turn_assembly_baseline.json](turn_assembly_baseline.json)、次回の変更手順は [turn-assembly スキル](../../.agents/skills/turn-assembly/SKILL.md) にある。

## 入力の範囲

次の13操作の長さ0〜4の全30,941列を、それぞれ4設定で実行する。
合計123,764ケースとなる。操作列の重複状態は除去しない。

| 操作 | 入力と意味 |
|---|---|
| `normal` | `教科書`、0.5秒。継続する名詞止め |
| `weak` | `この部分がですね。`、0.5秒。句点があっても継続する語尾 |
| `reject` | `原子の`、0.5秒。助詞止め |
| `predicate` | `同じです`、0.5秒。用言終止で即確定 |
| `strong` | `終わり！`、0.5秒。文末記号で即確定 |
| `long` | `教科書`、1.5秒。時間上限を超える断片 |
| `gap` | 次の断片の開始時刻を0.5秒進める。製品メソッドは呼ばない |
| `reserve` | `reserve_turn_id` を呼ぶ |
| `preview` | `preview` で途中字幕を作る |
| `boundary` | `on_boundary` で無音境界を通知する |
| `flush` | `flush` で保留を確定する |
| `reset` | `reset` で保留と予約を明示的に捨てる |
| `discard` | `discard_reserved` で断片のない予約だけを捨てる |

断片の先頭には列内で一意の `【1】` などを加え、同じ語でも欠落・重複・順序逆転を区別する。
ASR時間は断片番号×7ms、確定時刻は100＋断片番号×0.25秒とし、音声時刻とは独立させる。
時刻は0秒から始まり、断片長と `gap` に応じて進む。実時間は待たない。
任意の空文字、フィラーの完全一致、全ての語尾や日本語の意味は網羅しない。

| 設定 | 戦略 | 断片数上限 | 時間上限 |
|---|---|---|---|
| `simple` | simple | 2 | 1秒 |
| `count` | morph | 2 | 100秒 |
| `span` | morph | 12 | 1秒 |
| `default` | morph | 12 | 30秒 |

短い列で上限の直前・一致・超過を通すため、個数と時間を別の設定で小さくする。
時間上限は無音を含む先頭から末尾の幅、`audio_s` は断片の音声長の合計である。
既定の12断片・30秒を実際に満たす長さの列は探索しない。

各操作後に `has_pending` と `current_turn_id` を照合する。
各列の末尾には探索長の外で `flush` を2回追加し、残りの全文と二重確定がないことを確認する。
全ての接頭部も独立した列として探索するため、途中で reset が内容を捨てる前の保留も末尾 flush を通して確認できる。

## 判定する性質

| 性質 | 判定 |
|---|---|
| `conservation` | 確定文は保留断片の入力順の連結であり、件数と `merged` も一致する |
| `metadata` | 先頭・末尾時刻、ASR時間の合計、最後の確定時刻、音声長の合計が一致する |
| `termination` | simple、文末、個数・時間上限、boundary、flush の条件と理由でだけ確定する |
| `turn_identity` | 初期値1の連番を予約し、同じ発話で保持し、確定・空の破棄・reset 後には解放して再利用しない |
| `preview_text` | 途中字幕は保留全文と今回の途中認識の連結であり、後の確定文に途中認識を混ぜない |
| `preview_revision` | 同じ発話では版番号が1から増え、次の発話で1へ戻る |
| `pending_state` | `has_pending` は未確定の断片があるときだけ真になる |

違反したケースは最初の不一致で止める。
`violations` は性質ごとに観測した最短の `trace` と `expected`、`actual` を残す。
先に失敗する別の性質が後続の違反を隠すことがあるため、全ての潜在的な違反の最短性を保証しない。
`--case normal,preview,flush --profile default` で一列だけ再実行できる。

## 検出器が失敗することを確認する

`--mutation-check` は一時コピーの `server/turn/assembler.py` を12通り、別々に壊す。
元の製品コードには書き込まない。各専用ケースの正常時 PASS を確認してから、子プロセスで破壊版を実行する。
終了コード1と狙った性質の違反が揃った場合だけ `detected: true` にする。
Traceback、破壊箇所の不一致、予想外の性質違反だけの失敗は検出成功に数えない。
元コードの全探索が FAIL なら、その反例を出力し、`mutation_check_skipped` を付けて破壊検出を省略する。
元コードの不具合を、正常であるべき専用ケースの失敗として隠さないためである。

破壊は、後続断片の破棄、順序逆転、ASR時間の合算忘れ、無音を音声長に加算、個数上限の無視、時間上限の無視、確定済み ID の保持、途中字幕からの保留全文の除去、版番号の停止、保留中 ID の誤破棄、reset での ID 再利用、保留状態の隠蔽である。

例えば後続断片を捨てる破壊では、次の反例を得る。

1. `normal` で `【1】教科書` を保留する。
2. `normal` で `【2】教科書` を入力するが、破壊版は保持しない。
3. `flush` の期待値は2断片の全文だが、実際には1断片しか返らない。

同期コミット `5e97453303cacd166f7944b5442881ac2f9e362d` の製品コードは全探索で PASS、12破壊は全て検出できる。

## 対象外

VAD・PCMの保持、ASR、幻覚除外、分類器の言語的正しさ、翻訳、キュー、配信、記録、ブラウザー表示は実行しない。
Pipeline の古い途中認識を捨てる判定も、この検証では実行しない。
単一 ASR ワーカーから呼ばれる同期処理の契約を照合し、存在しない並行操作や推論待ち中の割込みは追加しない。
入力オブジェクトの外部からの変更、異常な時刻・設定、任意の長さの列も保証しない。
