# 50分授業の継続と推論ハング

受理した音声を処理待ちの排出を待たずに流し続けても、指定した処理時間内で英語・中国語の字幕が届き、保持する状態が上限を超えないことを確認する。
もう一つの要求は、推論が戻らなくても後続の字幕処理とサーバー終了が回復すること。違反すると授業の途中で字幕が止まり、通常の終了操作でもプロセスが残る。

既存の `lesson-liveness` は推論が最終的に戻ることを仮定し、600件ケースも各発話の排出を待つ。この仮定を外す箇所を次の検証対象に選んだ。
実行手順と同期確認は [lesson-endurance スキル](../../.agents/skills/lesson-endurance/SKILL.md) にある。

## 道具と範囲

Python 3.12.10 と `scripts/formal/requirements.txt` の固定依存で実コードを実行する。
asyncio、標準Future、音声の分割、字幕配信を手書きの別言語モデルへ置き換えず、期限の有限集合と長い固定入力を検査する方法を選んだ。
SMTによる証明、任意の入力・所要時間・スレッド順序の証明ではない。実モデルの性能は実時間試験で別に測る。

`Model the Domain` 原則に従い、時計は100ms単位のtick、推論の終了予定はtick上の期限として持つ。
`TimedExecutor` は既存の `ControlledExecutor` と標準Futureの取消し規則を使い、実行先を一つに保つ。モデル内部の計算だけを決定的な代役にする。
`Pipeline`、`InferenceRunner.run`、ASR待ち行列、MT待ち行列、字幕履歴・キャッシュ・受信者の処理は製品コードである。

| 検査 | 有界の入力 | 確認する結果 |
|---|---|---|
| 正の期限 | 期限1秒、完了0.9・1.0・1.1秒 × tickのタイマー処理前後の完了通知、計6ケース | 期限前は成功、期限後は待機終了。同時境界は成功・期限切れのどちらも許す。その後の正常要求が成功する |
| 50分の入力 | 発話4秒または29秒＋無音1秒 × ASR 0.1・0.4秒 × 言語ごとのMT 0.2・1.5秒、計8構成 | 各3000秒、600件または100件。入力IDから作る独立の期待列と、先生の認識・英中字幕が一致する |
| 保持量 | 各100msのコールバック処理後 | ASR音声30秒、MT待ち256件、履歴50件、キャッシュ512件、受信者の控え100件以下。タスク数は開始時＋4以下 |
| 字幕期限 | 各発話の音声末尾から8秒 | その時刻までに必要な件数が届く。最終的な列比較で内容・順序・重複も確認する |
| 最終排出 | 入力終了から10仮想秒後 | 待ち行列、ASR音声、実行中ASR・MTがすべて空 |

VADはenergy、閾値300、終端無音100ms、pre-rollなし。Turnはsimple、partialは無効。
毎tick、推論の完了通知、16周回のコールバック処理、100msのPCM入力、16周回のコールバック処理の順で進める。
発話ごとの `drain` は呼ばない。初期化・終了と確認用の10秒は3000秒の音声に含めない。
8構成のすべての組合せは調べるが、発話ごとに所要時間が変動する全順序や、余裕のない処理時間を網羅しない。
保持量は上記のコンテナーとタスク数の検査であり、Python全体やnativeモデルのRSS上限の証明ではない。

## 永久ハングからの字幕再開と終了

ASRとMTそれぞれで本番の `ProcessInferenceRunner` を使う。
モデルの代役は、入力IDが1または3のときだけ、ファイルによる解放通知を待ち続ける。
子プロセスを交換しても正常入力IDが再び停止しないよう、停止条件を入力に結び付ける。
子が到達マーカーへ実PIDを書き、親はWindowsの読取専用プロセス待機API、またはPOSIXの存在確認で生存を調べる。

1. 初期ロードの完了を待ち、その所要時間を別に記録する。
2. 入力1の推論が停止箇所へ入ったことを確認し、解放せずに呼出側の期限2秒を待つ。
3. 先生への期限切れ通知と旧PIDの消滅を確認する。
4. 正常な入力2を送り、8秒以内に英中それぞれ1件の字幕を要求する。発話番号、原文、言語、訳文を独立した期待値と照合する。
5. 入力3を送り、再び停止箇所へ入ったPIDがまだ生きている間に `Pipeline.stop` を呼ぶ。
6. 停止の帰還、生成した全PIDの消滅、その後の外側Pythonの正常終了を確認する。

最初の停止だけを期限前に解放する対照もASR・MTそれぞれ実行する。
合計4ケースの結果と初期ロード時間、後続字幕までの観測時間、各PIDを [基準結果](lesson_endurance_baseline.json) に記録する。
外側Pythonの結果待ちは35秒、結果保存後の停止・終了待ちは別の2秒とする。
結果がない場合や検証器のクラッシュは環境または検証器の失敗として扱う。

Issue #180の修正前は、実行中の単一スレッドを取り消せず、永久停止後の字幕とPython終了が両方失敗した。
実行先を停止可能なプロセスへ変えたため、検証もその実行先を使う。
以前の0.6秒は製品の復旧SLOではなく、ロード済みスレッドの復旧観測幅だった。
現在の後続要求は子の生成とモデルの再ロードも含む。2秒の呼出期限と8秒の観測幅は、この代役モデルを使った試験の有限な監視時間であり、実モデルの復旧時間を保証しない。

モデルごとの直列性と取消しの旧契約は、制御Executorと `inference-lifecycle` で引き続き検証する。
プロセスの起動待ち、短い期限での共有ロード、起動中の停止、待機者の取消し、反復停止、再キャンセルは `tests/unit/test_inference_process.py` でも確認する。
`lesson_liveness_real.py` は `create_app` の未注入経路で実モデルを反復実行し、正常な停止後のPID消滅を確認する。
既定60秒のまま50分間ハングを観測する試験、実モデルでの自然発生ハング、全OSの終了順序、記録保存の完了は対象外。

## 破壊と復元

通常の制御ケースが成功した後に、一時コピーの製品コードを1箇所ずつ壊す。
5種類すべてで指定した性質の違反を取得し、元の内容に戻した同じコピーで正常な制御ケースへ戻ることを確認する。

| 破壊 | 検出する性質 |
|---|---|
| 呼出側の期限を2倍にする | `positive_deadline` |
| ASRワーカーを300回で終了させる | `worker_liveness` |
| MT投入後の起床通知をなくす | `caption_deadline` |
| 翻訳キャッシュの追い出しをなくす | `retained_state_bound` |
| 配信する訳文を別の文字列にする | `caption_delivery` |

破壊検査は制御Executorの性質を対象とする。プロセス復旧の4ケースは別に実行する。
例外、検証用の外側Pythonの期限超過、置換箇所の不一致は破壊検出成功に数えない。

## 実時間の50分試験

既存の `replay_client.py` を使い、100ms等速で3000秒の合成音声を送る。
実際のHaas-jaとHy-MT2、Silero VAD、morph Turn、英語5人・中国語5人のWebSocket接続を使う。
反復音源が翻訳キャッシュへ当たり続けるのを防ぐためキャッシュを0にする。短い音源を `--audio` で指定すると50分へ伸びないため、この手順では既定コーパスを使う。

`lesson_endurance_report.py` は既存のsource manifest、依存・モデル・入力・レポートの照合と再確認を行い、その後、次の条件をすべて要求する。

- 3000秒以上の計測と96,000,000 bytesの予定・実送信の一致。
- 実ASR・MTの呼出し、翻訳キャッシュヒット0、10人・英中各5人。
- 接続失敗、クラッシュ、音声破棄、先生へのエラー通知が0。
- 確定した全発話について全生徒の欠落0。履歴50件への縮小で以前の欠落を隠さない。
- 5分窓10個のすべてに字幕。字幕遅延の中央値5秒以下、最大8秒以下、遅延悪化なし。
- RSS 5000MB以下、資源の増加傾向なし。資源と統計の観測間隔の最大欠落6秒以下。
- 最終統計のASR待ち・実行中音声量とASR・MT待ち行列が0。既存の受け入れ判定も成功。

この判定は1回の観測である。モデルの認識・翻訳の意味的な正確さ、ASRが空文や幻覚除外で出力しなかった発話の完全性、全ての授業音声、別のサーバーPC、実LANやマイク、生徒画面の表示時間を保証しない。
遅延値はTurn確定から字幕送出までであり、物理的な発話終了からDOM表示までではない。
ASR内部例外は製品側でログのみの場合があるため、保存された `server-hy-mt2.log` のエラーも確認する。
実測結果は [実行記録](lesson_endurance_run.md) に記載する。
