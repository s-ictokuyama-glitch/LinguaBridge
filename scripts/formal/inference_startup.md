# モデルの準備停止と授業の字幕継続

音声認識・翻訳の子プロセスには、要求ごとの期限と独立したモデル準備の期限がある。授業途中に再生成した子の factory や warmup が永久停止しても、準備期限後にその子を回収し、後続音声の英語・中国語字幕を再開する。

この検証は [inference-startup スキル](../../.agents/skills/inference-startup/SKILL.md) から実行する。製品の状態を手書きモデルへ置き換えず、Python 3.12.10 で実際の `ProcessInferenceRunner`、子プロセス、`Pipeline` を動かす。検証結果は [基準結果](inference_startup_baseline.json) に保存する。

## 選んだ対象

既存の [lesson-endurance](lesson_endurance.md) は、50分の仮想時間入力と、認識・翻訳本体の永久停止からの復旧を確認する。[推論ハング復旧の記録](inference_recovery_run.md) では、モデル準備自体の永久停止を自動復旧の対象外としていた。

通常テスト `tests/unit/test_inference_process.py` は、遅い準備の共有、準備期限、待機者がいないときの回収、停止との競合を確認する。この検証では、準備待ちの操作列と、授業途中の再準備が停止した後の字幕経路を確認する。

## 実装上の経路

`server/inference_process.py` の `_serve` は、factory と warmup を完了した後で起動応答を返す。`run` はその応答を `asyncio.shield` で待つ。要求送信前の待機中は `active` が未設定であり、要求が期限切れになってもその世代を回収しない。

この共有待機は、短い要求期限のたびに正常な重いモデル準備をやり直すことを防ぐ。`_get_generation` は `process.start()` の直前に準備期限を固定する。`_prepare` 自身がその期限で待ち、期限超過や準備失敗なら `_retire` を予約して失敗結果を返す。回収をその場で await しないため、回収側が準備タスクの終了を待つ経路と循環しない。後続要求は旧世代の回収完了後に次世代を生成する。

`limits.inference_startup_timeout_s` は ASR・MT 共通の正かつ有限な秒数で、既定値は120秒。初回準備にも同じ期限が適用され、失敗時は既存のログを残して `/ready` が503を返す。初回の自動再試行は追加していない。120秒は調整可能な運用上の初期値であり、実モデルの正常準備時間や復旧時間の保証ではない。同期処理である `process.start()` 自体は中断できず、戻った時点で期限を超えていれば準備失敗として回収する。

ASR は音声断片ごと、MT は発話と言語ごとに要求を出す。MT の英語要求が停止した場合は、同じ発話の中国語要求が再生成を始めることもある。

## 有限探索の範囲

実際の子プロセスを factory または warmup 内で止め、最初の要求の期限切れ後に、次の逐次操作列をすべて実行する。

| 項目 | 範囲 |
|---|---|
| 操作 | `deadline` は新しい翻訳要求の正の期限を切らす。`cancel` は起動待ちへ入った要求を取り消す |
| 長さ | 0〜3。計15列 |
| 停止位置 | factory、warmup |
| 終端 | 準備を解放して翻訳、または準備を止めたままclose |
| 組合せ | 15列 × 2箇所 × 2終端 = 60ケース |

これは逐次操作列の網羅であり、同時要求やすべてのasyncio割込み順序の網羅ではない。

検査する性質は、要求の期限・取消しが共有する準備を壊さない `startup_waiter_isolation`、準備解放後の正しい翻訳 `startup_resumption`、停止時の子回収 `startup_shutdown` である。

字幕経路はASR・MT、factory・warmup、準備の解放有無を掛け合わせた8ケースを使う。`startup_recovery` は後続音声の英語・中国語字幕への到達を検査する。実 `Pipeline`、プロセス版Runner、energy VAD、simple Turn、受信記録用の接続代役を通し、推論計算だけを決定的な代役にする。

音声はID 0〜4の5件で、ID 0は障害前の正常字幕、ID 1は実行中処理の停止、ID 2は準備停止後の要求、ID 3と4は後続字幕の判定に使う。要求期限は1秒、準備期限は5秒とし、各入力の後にASR・MTの排出を待つ。MTではID 1の中国語とID 2の英中要求が準備を待つため、解放対照は累積3要求分より長い準備期限を使う。継続的な実時間入力速度を測る試験ではない。

解放しないケースは、ID 2の排出後、新しい要求を出さずに準備中PIDの消滅を確認してからID 3と4を送る。回収されなくても後続音声を送り、実際の英中字幕を記録して `startup_recovery` 違反にする。解放対照は同じPIDのまま後続字幕が届くことを要求する。

## 検証器の感度

製品コードの一時コピーにだけ、次の破壊を入れる。

| 破壊 | 検出する性質 |
|---|---|
| 起動待ちのshieldを削除 | `startup_waiter_isolation` |
| 準備後の翻訳結果を別の文字列に置換 | `startup_resumption` |
| close時の世代回収を省略 | `startup_shutdown` |
| 準備期限を無期限に置換 | `startup_recovery` |

各破壊は対象の性質で失敗し、元へ戻すと正常対照が成功することを要求する。単なる例外や外側監視の期限超過は検出成功に数えない。

準備期限を無効にする破壊はASR・MT、factory・warmupの4条件で実行し、待機者なしでの回収と後続字幕の観測を残す。4件すべて `startup_recovery` 違反を検出し、復元後は `PASS` に戻ることを要求する。

## 反例の読み方

永久停止ケースでは、初めに正常な音声から英語・中国語字幕を届ける。その後に認識または翻訳本体を停止させ、期限後の子プロセス回収を確認する。次の世代だけを factory または warmup 内で停止し、その先の世代は正常に動けるようにする。

準備期限を無効にした場合は、同じ準備中の世代が残り、後続字幕が届かない。終了時の `Pipeline.stop` と全子 PID の回収は字幕再開と別に判定する。正常に遅い準備を共有する対照も維持する。

## 保証の限界

有限の操作列と実プロセスの固定ケースに限った検査であり、無制限の形式証明ではない。全 OS スケジュール、すべてのタイミング、子プロセス生成の失敗、任意のモデル内部動作は網羅しない。

音声と認識・翻訳結果は決定的な代役を使う。マイク、実 LAN、生徒画面、字幕の意味精度、記録保存、実モデルの自然発生ハング頻度は測らない。既定60秒の要求期限を待つ50分試験や、サーバーPCでの性能測定の代わりにはならない。

検証用の短い期限と外側の監視時間は、実行を有限にし子プロセスを残さないための設定である。製品の復旧時間の保証として扱わない。
