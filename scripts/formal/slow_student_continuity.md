# 遅い生徒がいる授業の字幕継続

## 選定理由

先生の音声を受け付け続けても、1台の送信待ちが翻訳ワーカーを止めれば、全生徒の字幕が止まる。`server/delivery.py` の製品契約は、接続ごとの送信キューでこの影響を分離することにある。

既存の [client-delivery](../../.agents/skills/client-delivery/SKILL.md) は送信口の有限探索と4回の直接broadcastで分離を調べる。音声入力、翻訳、字幕履歴の実処理は含まない。[student-continuity](../../.agents/skills/student-continuity/SKILL.md) はPCMから字幕まで通すが、送信が正常に完了すると仮定する。今回の検証は、この二つの間にある送信障害と授業処理の接続部分を扱う。

ほかの候補には、先生側WebSocketの送信待ちと、既定Sileroの32msフレーム・推論状態がある。前者には製品の明示的なバッファ上限がなく、後者にはモデル境界の独立した検証が必要になる。今回は、製品が明示する障害分離を音声入力から確認する対象を選んだ。

## 実コードと入力の関係

正常な英語・中国語の生徒に、送信を保留できる生徒を追加する。音声認識と翻訳の計算は入力IDから結果を返す代役とし、PCM変換、energy VAD、morphの発話確定、ASR・MTの待ち行列、字幕履歴、接続ごとの送信は製品コードを動かす。

期待する発話と訳文は音声入力の台帳から求める。正常な生徒について、内容、順序、重複、接続継続を比較する。受信の観測地点は制御Socketの `send_json` が正常完了する時点であり、送信キューの受付結果ではない。障害生徒の送信完了を待たずに、新しい音声から字幕が届くことを要求する。

Pythonのasyncioと実際の待ち行列を直接実行するため、別言語の手書き状態モデルではなく、Pythonで有限操作列を全列挙する。これは指定した操作・長さ・スケジューラーの有界検査であり、SMTや証明支援系による無制限の証明ではない。

## 探索と連続入力

有限探索は `sentence`、`asr`、`mt`、`send_ok`、`send_error`、`send_timeout` の長さ0〜4、送信容量2・3件を調べる。3,110候補のうち、完了対象のFutureが存在するなどの条件を満たす180列が合法で、すべて成功した。容量1件は正常な先生向け通知のバーストも収まらないため、この障害分離の入力条件には使わない。

初期状態では追加生徒の最初の字幕送信を保留する。各操作後は16回イベントループを進める。末尾はASR・MTを公平に正常完了させ、追加のPCMから後続字幕が届くことも確認する。有限探索のタイムアウトは結果の注入であり、時間の経過は固定ケースと連続入力で別に調べる。

| 固定ケース | 確認すること |
|---|---|
| `overflow` | 送信保留中の満杯による1013切断と正常生徒への後続2字幕 |
| `error` | 送信例外による1013切断と正常生徒への後続2字幕 |
| `timeout` | 実 `wait_for` の0.5秒期限を仮想時計で超過し、0.4秒では接続中、0.6秒では切断済み |
| `recovery` | 送信成功済み `last_seq=1` の後に失敗し、実 `Lesson.join` で欠落3字幕と新しい1字幕を受け取る |

50分入力は100msのPCMを30,000回与える。10秒ごとに文中断片・文末・長無音を含む計画を繰り返し、900断片から600発話を確定する。追加生徒を20秒ごとに交換し、送信満杯・例外・1秒の送信期限超過を各50回起こす。正常な英中生徒は接続を維持する。交換時は実 `Lesson.leave` と `Roster.add` を使い、履歴復元は固定ケースだけで調べる。

ASRと言語ごとのMTには各0.8仮想秒を与える。各発話を8仮想秒以内に配信し、全体の末尾10仮想秒で排出する。発話ごとのdrain待ちや末尾flushで遅延を隠さない。通常の送信期限は3600秒として満杯と例外を分離し、統計配信は間隔3600秒で抑制する。

基準結果は正常英中生徒が各600字幕を受信し、音声破棄は0件。送信待ちは最大2件、字幕履歴50件、キャッシュ512件、受信記録100件、接続4本、生存タスク8個であった。これらは設定・入力計画内の観測値である。

## 破壊で検出能力を確認する

製品ソースの一時コピーを13通りに変更し、次の違反を検出した。各コピーには1つだけ変更を適用し、元コードの同じケースが成功することも確認する。

| 一時的な変更 | 検出する性質 |
|---|---|
| 翻訳ワーカーからソケット送信を直接待つ | `slow_isolation` |
| 字幕の訳文を壊す | `bilingual_delivery` |
| 送信キューの容量をなくす | `send_queue_bound` |
| 送信例外による切断を省く | `fault_disconnect` |
| 送信期限超過による切断を省く | `fault_disconnect` |
| 送信期限を半分にして早く切断する | `positive_timeout` |
| drainで翻訳の完了を待たない | `drain_completion` |
| 再参加時の復元を省く | `recovery_delivery` |
| 字幕履歴の容量をなくす | `retained_state_bound` |
| 長無音による発話確定を遅らせる | `sustained_deadline` |
| 後続PCMを破棄する | `audio_admission` |
| ASRワーカーを1件で終了する | `worker_liveness` |
| 停止時に接続を回収しない | `stop_completion` |

例えば直接送信を待つ破壊では、先生の1発話から正常生徒へ字幕を送る途中で、追加生徒の送信Futureを待ち続ける。推論を完了させてもMTの排出が終わらず、`slow_isolation` が「排出待ちのまま」と報告する。例外終了や子プロセスの時間切れを、この検出の代用にしない。

元コードで全探索と50分入力を再実行し、`restored: PASS` と `restored_matches: true` を確認した。

## 結果の読み方

実行手順は [スキル](../../.agents/skills/slow-student-continuity/SKILL.md)、保存した結果は [基準結果](slow_student_continuity_baseline.json) にある。終了コード0は範囲内の成功、1は性質の違反、2は環境または検証器の失敗を表す。

反例では `property`、`trace`、`expected`、`actual` を読み、送信ゲートと推論完了の順序を製品のawait境界へ対応させる。環境の停止、JSONの欠落、故障注入箇所の不一致は製品の反例に数えない。現行コードの違反が見つかっても期待値を弱めず、製品変更は別の依頼で行う。

## 限界

50分は3000秒の仮想音声入力であり、実時間50分の性能試験ではない。実LAN、物理マイク、ブラウザーの描画、認識・翻訳の意味精度、Silero、推論プロセスの永久停止は扱わない。保持量の上限は観測するコンテナーとタスク数だけで、プロセス全体のメモリー量ではない。

ソケットcloseは完了すると仮定する。`ClientSender.aclose` は既に始まったcloseを期限なしで待つため、この検証の成功はclose永久停止時の終了時間を保証しない。正常な生徒への字幕継続と、サーバーの終了が戻ることを区別する。

実モデルでの50分の計測には [lesson-endurance](../../.agents/skills/lesson-endurance/SKILL.md) の別コマンドを使う。
