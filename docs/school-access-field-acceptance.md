# 学校で配布版の起動と字幕を確認する（#151）

[Issue #151](https://github.com/s-ictokuyama-glitch/LinguaBridge/issues/151) の現地記録票です。#148〜#150 を含む同じ ZIP で、開発機での配布確認と学校での受入を行います。

**現地確認待ち。** 実施日にこの記録票をコピーし、`docs/school-access-field-results-YYYY-MM-DD.md` に結果を保存します。

## 配布前に記録する

| 記録項目 | 結果・証拠 |
|---|---|
| ZIP 名、SHA-256、`app/version.json` のコミット、ビルド日時、`dirty` | 未記録 |
| 開発機のビルド結果と同梱 Python の自己検証ログ（`/ready` の HTTP 200 を含む） | 未確認 |
| 配布 ZIP を展開して実モデルで起動した結果と `/ready` の HTTP ステータス | 未確認 |
| 切り戻し用の動作確認済み ZIP 名または旧版の保管場所 | 未記録 |

ビルドの `/ready` 自己検証と、配布 ZIP を展開して実モデルを起動した結果は別々に記録します。展開後は起動画面の HTTP ポートを使い、サーバーPCで `http://127.0.0.1:<HTTPポート>/ready` を開きます。実モデルの準備が済んで HTTP 200 を確認したら、実施日時と証拠を表に記録します。

## 学校で試す

実施日時とタイムゾーン、担当者、サーバーPCの Windows 版、各端末の機種・OS・ブラウザ版、接続した Wi-Fi を記録します。配布前に控えた ZIP と照合してから展開します。既存環境を更新する場合は、停止後に旧版の `app` と `start.bat` を退避し、`data` を引き継ぎます。展開と初回起動は[先生向け運用手順書](../README.md#先生向け運用手順書)を参照します。

| # | 確認 | 判定 | 時刻・観測・証拠 |
|---|---|---|---|
| S1 | サーバーPCで `start.bat` を開く。先生画面が自動で開き、モデル準備後にサーバーPCの `/ready` が HTTP 200 を返す。 | 未確認 | |
| S2 | サーバーPCの先生画面で「開始」を押す。必要ならマイクを許可し、授業が始まり発話を認識することを確認する。 | 未確認 | |
| S3 | 同じ校内 Wi-Fi のスマートフォンで先生画面の QR をカメラから読み取る。生徒ページで言語を選んで参加し、先生画面の人数が増えることを確認する。 | 未確認 | |
| S4 | 先生がテスト用の発話をする。スマートフォンに、選んだ言語の翻訳字幕が表示されることを確認する。 | 未確認 | |
| S5 | サーバーPCの別のターミナルで `.\start.bat --diagnose` を実行する。採用IP、HTTP・HTTPS のポート、実 Wi-Fi の IPv4、診断の判定と証拠を記録する。 | 未確認 | |
| S6（任意） | 起動画面で先生コードを確認し、サーバーPCの先生画面を閉じる。別端末で先生用 HTTPS URL を開き、先生コードを入力して参加する。「開始」を押し、マイクを許可して授業を始められるかを確認する。 | 未確認 | |

S1〜S5 は必須です。接続に失敗しても S5 は実行し、最後に成功した段階、最初に失敗した段階、画面のエラー、対応する診断結果とログの時刻を記録します。診断の終了コードと、診断の各項目や実端末で確認した結果は分けて記録します。診断の読み方は[接続診断手順](connection-diagnostics.md)を参照します。

判定には「成功」「失敗」「未確認」「根拠付き非該当」「合意により省略」を使います。配布前の確認と S1〜S5 がすべて成功したら、必須項目を合格と記録します。上流の失敗で試せなかった項目は「未確認」とし、該当する試行番号を記録します。S6 で問題が出た場合は、端末、最終URL、TLS またはマイクのエラー、再試行手順を後続 Issue に記録し、そのリンクを報告に残します。公開する URL・画像・ログでは参加コード、先生コード、QR、秘密鍵、授業音声を伏せます。

## 問題が出た場合は旧版へ戻す

1. 新版の ZIP 名、失敗時刻、最初に失敗した確認番号と診断結果を控えます。
2. 新版を停止します。新版の `app` と `start.bat` を退避し、動作確認済みの旧版の `app` と `start.bat` を元の場所に戻します。証明書・授業記録・現地設定を含む `data` はその場所に残します。
3. 旧版の `start.bat` で起動し、`app/version.json` と `/ready` の HTTP 200 を確認します。学校での運用を再開する前に、先生と生徒が接続でき、翻訳字幕が届くことを確認します。
4. 旧版の版情報、再確認した操作と結果、残った問題を記録票に追記します。
