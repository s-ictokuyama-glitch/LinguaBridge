# Haas-ja の ASR 評価

Windows の CPU で、Haas-ja の fp32 版を sherpa-onnx 1.13.8、Kizuna の int4 / int8 版を ONNX Runtime 1.31.0 で試す。授業動画の書き起こしと正解文は教材の複製になるため、リポジトリ外に保存する。

## モデルの取得

`models.dir` に指定したディレクトリの下へ、固定リビジョンで取得する。以下は PowerShell の例。評価用の環境に Hugging Face CLI を入れてから実行する。

```powershell
$models = "$env:LOCALAPPDATA/LinguaBridge/models"
hf download oboroge0/Haas-ja-v1.0-onnx --revision 2c2133a4279fca8ee408dd33b5701690a0bd4f3f --local-dir "$models/haas-ja-v1.0-onnx" --include "encoder.onnx" "encoder.data" "decoder.onnx" "joiner.onnx" "tokens.txt" "LICENSE" "NOTICE"
hf download kizuna-intelligence/Haas-ja-v1.0-OneCompression-ONNX --revision e46a4b107ffba60336eb3de9745da6f628cfae35 --local-dir "$models/haas-ja-onecompression" --include "manifest.json" "common/*" "int4-onecomp/*" "int8/*" "LICENSE" "NOTICE"
```

[sherpa 版の固定リビジョン](https://huggingface.co/oboroge0/Haas-ja-v1.0-onnx/tree/2c2133a4279fca8ee408dd33b5701690a0bd4f3f) の推論ファイルを次に示す。`Get-FileHash` で照合できる。

Kizuna 版は、固定リビジョンに含まれる manifest を使う。ファイルの SHA256 は `93a64b20a6270fc6a75a897a869aa8d24594580321fb7e0ec814e2a5fe09e83d`。起動時に manifest 自体と、選択した形式の encoder、外部重み、共通ファイルを照合する。[固定リビジョンの manifest.json](https://huggingface.co/kizuna-intelligence/Haas-ja-v1.0-OneCompression-ONNX/blob/e46a4b107ffba60336eb3de9745da6f628cfae35/manifest.json)

直接デコードは、Kizuna Intelligence が公開したグラフ入出力、log-mel 特徴量、TDT デコードに合わせて実装した。元の Haas-ja-v1.0 は Third Intelligence が公開した。int4 の量子化には Fujitsu の OneCompression が使われている。[Kizuna の参照実装](https://huggingface.co/kizuna-intelligence/Haas-ja-v1.0-OneCompression-ONNX/tree/e46a4b107ffba60336eb3de9745da6f628cfae35/haas_cpu) [配布元の NOTICE](https://huggingface.co/kizuna-intelligence/Haas-ja-v1.0-OneCompression-ONNX/blob/e46a4b107ffba60336eb3de9745da6f628cfae35/NOTICE)

## 実行

以下のいずれかをリポジトリ外の上書き設定 `haas.yaml` に書く。

```yaml
asr:
  engine: haas-sherpa
```

```yaml
asr:
  engine: haas-onnx
  haas_onnx:
    quantization: int4 # または int8
```

```powershell
python -m server.main --config-override ../evaluation/haas.yaml
python scripts/lesson_asr_eval.py TestData/testdata.mp4 --config-override ../evaluation/haas.yaml --candidate-out ../evaluation/haas.json
```

`python -m pytest tests/integration/test_haas_asr.py` で、設定からエンジンを選び、既知の音声を先生の WebSocket から送って、生徒の字幕に「教科書の42ページを開いてください」が出ることを確認できる。既定の場所と異なるモデルディレクトリは `LINGUABRIDGE_HAAS_MODELS` で指定する。

## sherpa-onnx の互換性

Kizuna の int4 と int8 を sherpa-onnx 1.13.8 の `nemo_transducer` で開くと、どちらも `InitEncoder:204 'vocab_size' does not exist in the metadata` でプロセスが終了した。Kizuna 版は sherpa-onnx の NeMo 経路用のメタデータを持たず、エンコーダーの出力と予測器の状態の形も sherpa 版と異なる。Kizuna 版では ONNX Runtime から各グラフを呼ぶ。製品が渡す Segment は最大30秒。28秒を超える入力では近くの静かな位置を探して内部で分割し、結果を元の Segment の一つの書き起こしにまとめる。

## sherpa-onnx の hotwords

`haas-sherpa` の既定は `greedy_search`。hotwords を使う場合は `asr.haas_sherpa.decoding_method: modified_beam_search` と `asr.haas_sherpa.hotwords_file` を指定する。文字単位で照合するので、辞書の各文字がモデルの `tokens.txt` にあることを確認する。

同じ fp32 モデルと `modified_beam_search` で、既知音声 `tests/fixtures/ja/08.wav` をデコードした。hotwords なしでは「原子の数」、`風 :20` を指定すると「原子の風」になり、出力を変えられた。`数 :1.5` と `原子の数 :10` では元から正しかった出力がそのまま残った。効果を確認するために誤った候補も指定した試験で、認識精度の改善は未評価。

## 実行結果

fp32、int4、int8 の3構成でウォームアップが完了し、既知音声の原文が生徒側の WebSocket に届いた。授業動画では3構成とも同じ50 Segment を書き起こし、全 Segment に出力があった。最長 Segment は約29.57秒で、Kizuna 版の内部分割を通っても元の1 Segment に対応する出力を保存できた。
