## 1. ASR 精度（拡張コーパス ja_ext）

音源: `tests/fixtures/ja_ext/index.json`（29クリップ / 174.5秒、#22 で拡張）。CER は NFKC正規化＋句読点除去後の文字単位。

| モデル | CER | CER(句読点込み) | WER | 置換/欠落/挿入 | RTF中央値 | RTF最大 | ロード | peak RSS |
|--------|-----|----------------|-----|---------------|----------|--------|-------|---------|
| whisper small | **9.62%** | 10.51% | 14.52% | 65/15/3 | 0.273 | 0.491 | 0.7s | 375MB |
| kotoba-whisper-v2.0 | **3.94%** | 6.19% | 6.85% | 27/7/0 | 1.02 | 1.883 | 2.3s | 899MB |

- WER のトークナイザは `charclass`（文字種の切れ目で切る近似）。**別トークナイザの WER と比べないこと**。日本語の主指標は CER
- 句読点を除いて採点しているのは、#21 の通り ReazonSpeech K2 が語彙に `。！？` を持たないため。表記仕様の差でエンジン判定（#28）が決まらないようにしている

### デコード時間の固定費と限界コスト

発話を細かく割る変更（#27 の turn 連結、#29 の partial 字幕）は固定費を払う回数を
変える。`decode ≈ 固定費 + 限界コスト×audio_s` に分けておくと影響を見積もれる。

| モデル | 固定費 | 限界コスト | R² | 標本数 |
|--------|-------|-----------|-----|-------|
| whisper small | 1.088s | 0.0472s / audio_s | 0.782 | 28 |
| kotoba-whisper-v2.0 | 4.717s | 0.0357s / audio_s | 0.687 | 28 |

> 回帰の対象は発話クリップのみ。無発話クリップは下の通り桁が違い、混ぜると歪む。

### 無発話（雑音のみ）での挙動

実運用ではVADが雑音のみの区間を落とすためASRまで届かない（区切りの節: カード0件）。
この行は**VADを緩める変更を入れたときに何を払うことになるか**の値として読む。

> **この行だけ run 間の振れが大きい**（whisper small で観測: デコード 11.4〜18.4s、
> 幻覚 0〜14文字）。無発話入力では温度フォールバックが走り、CPU int8 の非決定性が
> 効くため。**1回の差を回帰と読まないこと**。

| モデル | 音源長 | デコード時間 | RTF | 幻覚文字数 |
|--------|-------|------------|-----|-----------|
| whisper small | 20.0s | 18.422s | 0.921 | 0 |
| kotoba-whisper-v2.0 | 20.0s | 4.864s | 0.243 | 3 |

採点対象は区切り注釈のあるクリップのみ（17件 / 104.5秒）。既存10文は `boundary_annotated: false` なので #22 の結論に従い除外している。

| 字幕カード数 | 22（期待 turn 数 19 / 比 1.16） |
| 平均文字数 | 22.5（中央値 24） |

| endpoint latency 中央値 | 512ms |
| endpoint latency 最大 | 512ms |

## 5. E2E（実サーバー + 擬似生徒）

2.0分 / 擬似生徒 10名（en・zh 半々）/ エンジン hy-mt2 / 音源は fixture ループ合成。

| 指標 | 値 |
|------|-----|
| caption 数 | 38 |
| **first caption latency** | 5.34s（配信開始→最初の字幕。最初の発話が終わるまでの待ちを含む） |
| **final latency 中央値** | 2.21s（基準 ≤5s） |
| final latency p95 | 3.2s |
| final latency 最大 | 3.4s（基準 ≤8s） |
| `audio_queue_seconds` 中央値 | 0.0s |
| `audio_queue_seconds` p95 / 最大 | 5.44s / 8.1s |
| キュー深度 中央値 / 最大 | 0.0 / 1 |
| 過負荷サンプル | 0 |
| CPU 中央値 / p95 / 最大 | 155.4% / 659.6% / 725.5%（1コア=100%、論理16コア） |
| RSS ピーク | 2680MB（基準 ≤5000MB） |
| RSS 増分（前半→後半） | +22MB |
| 切断 / 復元失敗 / クラッシュ | 0 / 0 / 0 |

- `audio_queue_seconds` は ASR待ち＋処理中の音声の秒数。2秒間隔のサンプリングなので、中央値0 / 最大が1発話ぶんという分布は「常に空か、1発話が処理中か」を意味する。**滞留が積み上がっているという意味ではない**（積み上がりは #25 の負荷条件で初めて出る）
- CPU はサーバープロセスツリー合計。論理コア数×100% が上限

> **2.0分は45分の受け入れ試験の代わりにならない**（N-08 のドリフト判定には短すぎる）。メモリ増分とキュー滞留の「初期値」として読むこと。45分の実走は別途必要。
