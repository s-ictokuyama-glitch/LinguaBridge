# 送信元をアプリの入口で制限し、先生コードで先生権限を分ける

## 背景

学校のネットワーク構成によっては、外部のアドレスからサーバーPCに届く。教室に公開する参加コードを先生も使うと、生徒が配信や記録を操作できる。[Issue #147](https://github.com/s-ictokuyama-glitch/LinguaBridge/issues/147)

## 決定

- HTTP、静的ファイル、WebSocket の入口で、ソケットの送信元を IP として解析する。Python の `ipaddress` で `is_global` が真になる送信元と、IP として解析できない送信元を拒否し、ログに残す。Uvicorn は転送ヘッダーで送信元を書き換えない。
- 授業は起動ごとに、生徒用の4桁の参加コードと先生用の6桁の先生コードを作る。WebSocket の参加時に役割に対応するコードを照合する。参加コードの照合に成功しても、先生コードの失敗回数は残す。
- 先生情報 API は、送信元がループバックか、ソケットが接続を受けた IP と送信元が一致する場合に先生コードを返す。HTTP と HTTPS で同じ規則を使う。別端末では起動画面またはサーバーPCの先生ページで確認した先生コードを入力する。

## 理由と影響

待ち受けは `0.0.0.0`、ファイアウォールは既存の `Profile Any` とする。現地では Windows のネットワークプロファイルがパブリックになる場合があり、サーバーPCと生徒端末は異なるサブネットにいた。ファイアウォールを `Private` や `LocalSubnet` に絞ると、現地の接続を止める恐れがある。配布済みPCの規則を変えるには、管理者による再設定も要る。

プライベートアドレス、共有アドレス帯、リンクローカル、ループバックからの接続は通る。VPNなどで非グローバルな送信元が割り当てられた場合も同じ規則が適用される。生徒用 QR と参加 URL には4桁の参加コードだけを使う。サーバーPCの先生ページは自動で参加し、先生コードは普段は伏せて表示する。
