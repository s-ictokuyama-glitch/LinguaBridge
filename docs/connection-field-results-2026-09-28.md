## 10054 と正常終了の停止

サーバーのウィンドウに次が繰り返し出た（9/28・9/29とも。時刻・送信元はログに出ないため、どの操作で出たかは照合できていない）。

```
ERROR:asyncio:Exception in callback _ProactorBasePipeTransport._call_connection_lost(None)
  File "asyncio\proactor_events.py", line 165, in _call_connection_lost
ConnectionResetError: [WinError 10054] 既存の接続はリモート ホストに強制的に切断されました。
```

9/28 の初出時点の接続は `127.0.0.1` だけで、別端末の接続前だった（サーバーPCで自動的に開いたブラウザとの接続と推定）。
配信・再接続には影響がなかった。CLOSE_WAIT の残留やハンドル数（465前後）の増加も見られなかった。

9/29 12:3x に Ctrl+C を押すと、終了案内が出ないまま、8443の待受だけが閉じ、8000は待受と `/healthz` 応答を続けた。
再度のCtrl+Cでは解けない構造のため、ウィンドウを閉じて終了した。9/28もウィンドウを閉じて終了しており、同じ状態だった可能性がある。

原因（同じ版の CPython 3.12.10・uvicorn 0.50.2 のソースで確認。現地のプロセス内部の観測ではない）:

1. `_call_connection_lost` は `shutdown()` の後で `close()` と `server._detach()` を呼ぶ。相手がRST済みで `shutdown()` が10054を上げると、この2つが実行されず、asyncio の Server は接続が残っていると数え続ける。
2. uvicorn の終了処理は `server.wait_closed()` を期限なしで待つため、HTTPS側の終了が戻らない。
3. uvicorn 0.50 の `serve()` は自前のシグナルハンドラを入れるので、`server/main.py` の共有ハンドラは上書きされる。Ctrl+C は最後に登録したHTTPS側にだけ届き、HTTP側へはHTTPS側の終了後に再送される。HTTPS側が終わらないため、HTTP側は動き続ける。

#42 の区分では (d)「それ以外」に当たる（#50）。ローカル再現（WinError 64 の accept 停止）とは別経路で、ログだけでなく正常終了に実害がある。
