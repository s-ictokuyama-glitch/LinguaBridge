# 設定を変えない接続診断（#36）

後日の実端末での協働診断（#37）は、[現地診断の進行・報告票](connection-field-report.md)をコピーして記録します。
起動案内と実Wi-Fi IPが違う場合は、[接続先の選択・復元手順](network-selection.md)を参照してください。
起動時に今回限りのIPを選択した場合、診断にも同じ `--advertise-ip <IPv4>` を渡してください。
証明書の不整合がある場合は、[再発行・一組の復元・ブラウザでの再確認手順](certificate-recovery.md)へ進んでください。
実施済みの観測は[2026年9月15日の現地診断結果](connection-field-results-2026-09-15.md)を参照してください。

利用者は、先生から案内されたURLを開き直し、開けなければ試した時刻と画面のエラーを担当者に伝えてください。
参加コードを伏せて共有してください。画面の「接続に困ったとき」からも同じ手順を確認できます。

## 設定担当者の入口

サーバーPCで起動ウィンドウを残し、別のターミナルでアプリのフォルダを開いて実行します。
サーバーが起動に失敗していても、Python環境と依存があれば診断できます。

```powershell
.\start.bat --diagnose
```

診断はセットアップ、モデルロード、証明書生成、管理者への昇格、ファイアウォール・実行ポリシーの永続設定変更を行いません。
通常起動と同じく子PowerShellプロセスだけに `-ExecutionPolicy Bypass` を指定し、OSに保存された実行ポリシーは変更しません。
Python環境が無い場合は未確認で終了します。管理ポリシー等でPowerShellが起動できない場合も設定を変えず、
次のPython入口を使います。カスタム設定でサーバーを起動した場合は、**同じ設定ファイル**を指定します。

```powershell
.venv\Scripts\python -B -m server.diagnostics --config config.yaml
.venv\Scripts\python -B -m server.diagnostics --config config.yaml --json > connection-report.json
```

`--json` は担当者向けの詳細と空の記録欄を出力します。リダイレクトで指定したファイル以外に診断結果を保存しません。
終了コード0は診断結果を出力できた意味で、接続成功の意味ではありません。設定を読めない場合は2です。
取得不能・タイムアウト・権限不足は未確認です。Windows以外ではOS情報を未確認とし、HTTP/TLSの確認を続けます。

| 状態 | 意味 |
|---|---|
| 確認済み / `ok` | 表示した確認事項が成功した |
| 失敗 / `failed` | 接続拒否、異なるHTTP応答、証明書不一致などを観測した |
| 取得済み / `observed` | 候補や待受情報を取得した。別端末の接続成功は未確認 |
| 未確認 / `unknown` | 未実施または取得不能。正常とは扱わない |

ネットワーク候補と採用IPは起動時のIPv4選択規則で算出します。Wi-Fiの実アダプターと照合してください。
候補が無い・曖昧な場合は採用IPと証明書検証を未確認とし、**別端末の接続先を案内しません**。
169.254から始まるアドレスもDHCP等の確認が必要です。
起動後に設定ファイルやネットワークが変わった場合は、現在の診断と起動時の表示が異なることがあります。
待受のアドレス・ポート・PID・プロセス名を併せて確認してください。
ランタイム版は診断を実行したPython環境のものです。別の環境でサーバーを起動した場合、その版までは確認できません。

## 観測結果から次の操作へ

以下の `<IP>`、`<HTTPポート>`、`<HTTPSポート>` は診断が表示する値に置き換えます。
固定のポートを前提にしません。サーバー稼働中の `/connection-help` には現在の設定値を入れたURLを表示します。

| 段階 | 確認と復旧の分岐 |
|---|---|
| ループバックHTTP | サーバーPCで `http://127.0.0.1:<HTTPポート>/healthz`。statusがokでなければ、起動ログ・設定ポート・待受PIDを照合。待受なしなら起動エラーを解消して通常起動をやり直す。別プロセスなら担当者が競合を特定してからアプリ側のポート変更などを判断する。診断はプロセスを停止しない。 |
| 採用IPのHTTP | 同じPCで `http://<IP>:<HTTPポート>/healthz`。ループバックだけ成功するなら採用IP、Wi-FiのIPv4、待受アドレスを照合。127.0.0.1だけの待受は別端末から使えない。通常起動は0.0.0.0で待ち受ける。 |
| 別端末のHTTP | 既存の社内Wi-Fiにつないだ別端末で同じ採用IPの `/healthz` を開く。サーバーPCだけ成功するなら、時刻を揃え、実Wi-Fi、最終URL、サーバーPCのファイアウォールの適用プロファイル・受信規則・ポート・プログラム・アドレス条件を確認する。変更が必要なら担当者がサーバーPCで必要な範囲を判断し、変更後に同じ診断と端末操作を再実施する。 |
| モデル準備 | `/ready` の503はモデル未準備。`/healthz` が成功していれば通信断と区別する。起動ログでロード中かモデル欠損・破損かを確認し、後者ならREADMEのモデル復旧手順へ進む。接続エラーだけを理由にモデルを再取得しない。 |
| TLS | 診断の証明書SANと採用IP、有効期間、鍵の一致、提供中証明書のSHA256一致、HTTPS死活確認を見る。不整合ならサーバー停止後、同じ設定・IPで `python scripts\make_cert.py --config <設定ファイル> --advertise-ip <IP> --force` を実行する。旧ペアは自動退避される。再起動後に同じ診断を実行し、提供中証明書とHTTPS応答を再確認する。別端末の信頼は別に確認する。 |
| 別端末のTLS | HTTPSを使う端末で `https://<IP>:<HTTPSポート>/healthz`。警告・管理ポリシー制限の文言を記録。承認できない場合は未解決として担当者へ引き継ぐ。HTTP成功をTLS成功に読み替えない。HTTPS未使用の端末は「未実施（未使用）」と記録する。 |
| ページ取得 | 生徒は `http://<IP>:<HTTPポート>/`、HTTPSの先生は `https://<IP>:<HTTPSポート>/teacher`。アドレスバーの最終URLのスキーム・IP・ポート・パスを確認。HTTPSへの自動変更や別のエラーページへの遷移も記録する。HTTPの200だけでは操作画面が動いたことにはならない。 |
| WS参加 | 生徒ページで参加して、接続状態と先生ページの人数を照合。失敗時は同じ時刻の起動ウィンドウのログ、取得できる場合のみブラウザのWSエラーを照合する。ページ取得成功とWS参加成功を区別する。コード誤り・人数上限などの表示に応じて担当者が対応する。 |

ファイアウォールはActiveStoreのプロファイルと対象ポートに適用しうる有効な受信規則を読み取ります。
ポート範囲やAnyも候補に含めます。ルールの取得に成功しても、他の制約・管理ポリシー・別端末の経路まで
評価できないため、**実効許可は未確認**のままです。ルールが無いことも通行不可の断定には使いません。
PIDが分かってもプロセス名の権限が無ければ、その名前はunknownです。

ping失敗やログ不在だけでAP分離と断定しません。「該当ログなし・原因未確認」と記録します。
HTTP・TLS・ページ取得・WS参加はそれぞれ独立して未確認を残し、最後に成功した段階と次に試す段階を引き継ぎます。

共通条件は**既存の社内Wi-Fiでの直接接続**です。変更対象はアプリとサーバーPCに限ります。
社内ネットワーク変更、代替接続、別端末の証明書導入・ポリシー変更は含めません。
現地操作は後日担当者と協働し、制約で確認できない段階を成功扱いにしません。

## 端末ごとの記録欄

診断は参加コードのAPI、参加WS、ログ収集を呼びません。秘密鍵はローカルのSSLライブラリによる照合だけに使い、
内容を診断結果へ出力しません。秘密鍵・証明書フォルダ一式を収集・添付しないでください。
手作業で記入するURL・エラー・ログ・スクリーンショットには参加コードが混ざり得るため、共有前に必ず伏せてください。
JSONにはサーバーPCのIP・プロセス・ファイアウォール情報が含まれます。担当者間で管理してください。

```text
時刻（タイムゾーン）:
診断に使用した設定ファイル:
端末・OSの版:
ブラウザの版（取得不能なら未確認）:
入力したURL（参加コードを伏せる）:
ブラウザの最終URL（参加コードを伏せる）:
サーバーPCのHTTP: 未確認
別端末のHTTP: 未確認
別端末のTLS: 未確認
別端末のページ取得: 未確認
別端末のWS参加: 未確認
実際のエラー（参加コードを伏せる）:
同じ時刻の対応ログ（参加コードを伏せる／無い・取得不能も明記）:
最後に成功した段階:
次に試す段階・担当者:
```
