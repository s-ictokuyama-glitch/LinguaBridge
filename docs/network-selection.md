# 起動案内とQRの接続先を選ぶ（#38）

## 採用の根拠

[Issue #37の現地結果](connection-field-results-2026-09-15.md)で、社内Wi-Fi
`10.53.64.130` に対し、VMwareの `192.168.74.1` が自動案内されていた。
実Wi-Fi IPを手入力するとChromebook Chrome・iPhone ChromeでページとWS参加に到達した。
この観測に基づき、IPの帯や末尾による順位付けをNICの状態・役割による選択へ変更した。

## 選択方法

`start.bat` は、稼働中で有効なIPv4を持つ物理NICが1候補なら自動採用する。
複数の物理NIC/IPがある場合、または指定IPが消えた場合は、起動ウィンドウに
NIC名・IP・役割の一覧を表示する。利用中の社内Wi-Fiの番号を入力する。
Enterや不正な番号は起動を中止する。仮想NICや役割不明のNICを自動採用しない。
OS情報が取得できない場合は、取得できた稼働中IPv4の明示選択を求める。
候補も取得できない場合は起動しない。

毎回同じ選択を使う場合は、変更前の値を控えて `config.yaml` の既存の `server:` 内を編集する。
次の値は現地観測例であり、当日の実Wi-Fi IPv4へ置き換える。

```yaml
server:
  advertise_ip: "10.53.64.130"
```

`null` は自動選択。選択設定はNICやIPをOSへ追加する設定ではない。
起動・診断・証明書CLIは同じ設定ファイルと選択規則を使う。
初回セットアップ時に複数候補で証明書生成が止まった場合も、この値を設定して再実行する。
設定を残さず今回だけ選ぶ場合は、以下の全コマンドに起動画面の**同じIP**を渡す。
起動ウィンドウでの番号選択も今回限りで、設定ファイルを書き換えない。

```powershell
.venv\Scripts\python -m server.main --open-browser --advertise-ip 10.53.64.130
.venv\Scripts\python -m server.diagnostics --advertise-ip 10.53.64.130 --json
.venv\Scripts\python scripts\make_cert.py --advertise-ip 10.53.64.130 --force
```

カスタム設定を使う場合は3コマンドとも同じ `--config <設定ファイル>` を加える。
証明書生成は自動では実施しない。再生成する場合はサーバーを停止してから実行する。
証明書CLIは旧証明書と鍵を一組で自動退避し、確定した公開IPをSANへ渡す。
再起動後の検証・復元・別端末の警告承認は [証明書の復旧手順](certificate-recovery.md) を参照する。
別端末への証明書導入やポリシー変更は行わない。

## ネットワーク移動と案内の停止

先生画面は表示中の参加情報を約5秒間隔で確認する（OS情報取得の時間を加える）。
選択したIP/NICの消失・停止、または自動選択結果の変化を検出すると、先生情報APIは503を返し、
先生画面は参加URL・QR・コードを消して再起動を案内する。取得失敗・通信断でも古い案内を消す。
検出後は同じIPが戻ってもサーバー再起動まで案内を再開しない。
既に読み取ったQRや紙に転記した起動URLは回収できないため、移動後は必ず再起動・再配布する。
死活確認 `/healthz` は接続先の選択と独立して使える。

## 元へ戻す

サーバーを停止し、`server.advertise_ip` を控えた元の値へ戻して再起動する。
元が未設定だった場合は行を削除するか `null` に戻す。今回限りの選択なら追加設定の復元は不要。
元のIPが現在のNICにない場合は、無効な値を使わず再選択を求める。
証明書も変更した場合は、必要に応じてサーバーPC内の退避ファイルを元の場所へ戻して再起動する。

## 検証と後続への引き継ぎ

自動テストは社内10系＋仮想192.168系、複数物理NIC、指定IP消失、IP変更、
起動案内・先生情報・診断・SAN・QRの一致と案内停止、外部接続ゼロを確認する。
開発PCのWindows列挙でもWi-Fi（物理）とVMware（仮想）の区別を確認した。
2026年9月16日、開発PCで新しい選択規則により `192.168.1.6` を採用し、
一時サーバーのループバックと同IPの `/healthz`、同IPの生徒ページ、
ループバックの先生情報APIがHTTP 200を返すことを確認した（音声・翻訳はフェイク）。
先生情報APIの参加URLも同じIPだった。テスト後に一時サーバーは終了した。
これらは変更後の社内実端末の到達証拠ではない。
2026年9月23日の現地外照合で、番号選択から起動画面・API・QR・証明書SANまでを通す一連の試験と、
選択設定の復元試験を追加した（[検証記録](network-selection-verification-2026-09-23.md)）。

**変更後の現地到達再確認は未実施・現地担当者待ち。**
